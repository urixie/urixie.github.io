FREERTOS · RTOS · SCHEDULER · TICK

FreeRTOS 基础概念与调度机制

FreeRTOS 是嵌入式项目中常见的轻量级实时操作系统内核。它主要解决多个任务如何共享 CPU、任务之间如何通信、如何等待事件、如何处理超时以及如何管理有限内存等问题。

学 FreeRTOS 不要一开始就背 API。建议先理解 4 个核心概念：任务、调度器、阻塞等待、同步通信。只要理解这 4 个点，再看队列、信号量、互斥锁和定时器就会清晰很多。

一、为什么需要 RTOS

在简单裸机程序中，通常只有一个 while(1) 主循环，所有任务都在主循环里轮询执行。当功能越来越多时，例如按键、显示、通信、采样、存储、网络、升级同时存在，裸机轮询会变得难维护。

  • 轮询任务多了以后，每个模块互相影响。
  • 某个函数阻塞太久，会拖慢整个系统。
  • 超时、等待、重试逻辑容易写得很混乱。
  • 模块之间缺少清晰的通信边界。

RTOS 的价值是把系统拆成多个任务，每个任务像一个独立小线程，由调度器负责在它们之间切换。

二、FreeRTOS 的核心对象

  • Task：任务，系统中的一个执行单元。
  • Scheduler：调度器，决定当前运行哪个任务。
  • Queue：队列，用于任务间传递数据。
  • Semaphore：信号量，用于事件同步或资源计数。
  • Mutex：互斥锁，用于保护共享资源。
  • Software Timer：软件定时器，用于周期或单次回调。

三、任务状态

FreeRTOS 中任务并不是一直运行。一个任务可能处于就绪、运行、阻塞、挂起等状态。理解任务状态，是理解 RTOS 的关键。

四、抢占式调度与优先级

FreeRTOS 常用抢占式调度。调度器总是优先运行最高优先级的就绪任务。如果一个更高优先级任务从阻塞态变成就绪态，它可以抢占当前低优先级任务。 

xTaskCreate(sensor_task, "sensor", 2048, NULL, 3, NULL);
xTaskCreate(uart_task,   "uart",   2048, NULL, 2, NULL);
xTaskCreate(led_task,    "led",    1024, NULL, 1, NULL);

vTaskStartScheduler();

优先级不是越高越好。高优先级任务如果长期不阻塞，会让低优先级任务没有机会运行。任务中应该通过 vTaskDelay、队列等待、信号量等待等方式主动进入阻塞态。

五、Tick 与系统节拍

Tick 是 FreeRTOS 的系统节拍。每次 Tick 中断到来，内核会更新系统时间、处理延时列表，并判断是否需要任务切换。 

// 延时 100ms，写法推荐用 pdMS_TO_TICKS
vTaskDelay(pdMS_TO_TICKS(100));

如果 Tick 频率是 1000Hz，一个 Tick 就是 1ms；如果 Tick 频率是 100Hz，一个 Tick 就是 10ms。工程中不要直接写 Tick 数，优先使用 pdMS_TO_TICKS()。

六、中断优先级注意事项

Cortex-M 上使用 FreeRTOS 时，中断优先级配置非常重要。能调用 FreeRTOS FromISR API 的中断，优先级不能高于内核允许管理的最高中断优先级，否则可能导致难以复现的异常。

  • 中断中调用队列、信号量等接口，要使用 xxxFromISR 版本。
  • 中断回调尽量短，只做数据搬运和事件通知。
  • 复杂处理放到任务中执行。
  • 中断优先级要和 configMAX_SYSCALL_INTERRUPT_PRIORITY 匹配。

七、工程使用建议

  • 每个任务职责要单一，不要一个任务包办所有功能。
  • 任务中避免长时间死循环占用 CPU。
  • 任务优先级要按实时性排序，不按“重要性”排序。
  • 通信优先用队列、通知、信号量，不要随意共享全局变量。
  • 开启栈水位检查，确认每个任务栈大小是否合理。
