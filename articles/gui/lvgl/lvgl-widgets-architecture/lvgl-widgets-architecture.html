LVGL 控件、布局与界面架构

介绍 LVGL 对象树、Flex/Grid 布局、样式与事件，以及界面与业务分离、观察者绑定和多页面管理的工程做法。

1. LVGL 的对象模型

LVGL 中一切控件都是对象（lv_obj_t），对象之间构成父子树：

  • 屏幕是树的根，lv_screen_active() 返回当前屏幕。
  • 子对象的坐标相对于父对象，父对象移动、隐藏、删除时，子对象跟随。
  • 删除父对象会自动删除所有子对象，页面切换时只需删除页面根对象。
lv_obj_t *scr   = lv_screen_active();
lv_obj_t *panel = lv_obj_create(scr);            /* 容器 */
lv_obj_set_size(panel, lv_pct(100), 80);
lv_obj_align(panel, LV_ALIGN_TOP_MID, 0, 0);

lv_obj_t *label = lv_label_create(panel);
lv_label_set_text(label, "Temperature");
lv_obj_center(label);

lv_obj_t *btn = lv_button_create(scr);
lv_obj_t *btn_label = lv_label_create(btn);
lv_label_set_text(btn_label, "Start");

常用控件：标签（label）、按钮（button）、开关（switch）、滑块（slider）、下拉框（dropdown）、圆弧（arc）、进度条（bar）、图表（chart）、表格（table）、键盘（keyboard）、标签页（tabview）、列表（list）、消息框（msgbox）。

2. 布局：Flex 与 Grid

手工计算坐标的界面难以维护，换一块分辨率不同的屏就要重新调整。LVGL 提供类似 CSS 的布局：

/* Flex：参数行纵向排列，每行左侧名称、右侧数值 */
lv_obj_t *list = lv_obj_create(scr);
lv_obj_set_size(list, lv_pct(100), lv_pct(100));
lv_obj_set_flex_flow(list, LV_FLEX_FLOW_COLUMN);
lv_obj_set_style_pad_row(list, 8, 0);

for (int i = 0; i < 4; i++) {
    lv_obj_t *row = lv_obj_create(list);
    lv_obj_set_size(row, lv_pct(100), LV_SIZE_CONTENT);
    lv_obj_set_flex_flow(row, LV_FLEX_FLOW_ROW);
    lv_obj_set_flex_align(row, LV_FLEX_ALIGN_SPACE_BETWEEN, LV_FLEX_ALIGN_CENTER, LV_FLEX_ALIGN_CENTER);
    lv_label_set_text(lv_label_create(row), param_names[i]);
    value_labels[i] = lv_label_create(row);
}
  • Flex：一维排列，适合列表、工具栏、按钮组。
  • Grid：二维网格，适合仪表盘式的多块数据布局。
  • 尺寸尽量使用 lv_pct() 和 LV_SIZE_CONTENT，界面可以适配不同分辨率。

3. 样式与主题

样式（lv_style_t）类似 CSS 类，可以被多个对象共享，并且按部件（part）和状态（state）分别设置：

static lv_style_t style_card;
static lv_style_t style_btn_pressed;

void ui_styles_init(void)
{
    lv_style_init(&style_card);
    lv_style_set_bg_color(&style_card, lv_color_hex(0x1E293B));
    lv_style_set_radius(&style_card, 8);
    lv_style_set_pad_all(&style_card, 12);
    lv_style_set_border_width(&style_card, 0);

    lv_style_init(&style_btn_pressed);
    lv_style_set_bg_color(&style_btn_pressed, lv_color_hex(0x059669));
}

/* 使用：默认状态应用卡片样式，按下状态叠加按下样式 */
lv_obj_add_style(panel, &style_card, LV_PART_MAIN | LV_STATE_DEFAULT);
lv_obj_add_style(btn, &style_btn_pressed, LV_PART_MAIN | LV_STATE_PRESSED);

工程习惯：

  • 样式变量必须是静态或全局的，对象只保存样式的指针，局部变量样式在函数返回后失效会导致显示异常或崩溃。
  • 颜色、圆角、间距等集中定义在一个文件里，相当于设计规范，修改主题只改一处。
  • 少用 lv_obj_set_style_xxx() 设置本地样式，大量本地样式会占用更多内存。

4. 事件处理

static void start_btn_cb(lv_event_t *e)
{
    lv_obj_t *btn = lv_event_get_target(e);
    device_t *dev = lv_event_get_user_data(e);
    lv_obj_add_state(btn, LV_STATE_DISABLED);    /* 防止重复点击 */
    app_post_cmd(CMD_START, dev->id);            /* 发消息给业务任务，而不是在回调里执行耗时操作 */
}

lv_obj_add_event_cb(btn, start_btn_cb, LV_EVENT_CLICKED, &g_device);

事件回调在 lv_timer_handler() 中执行，回调里不能做耗时或阻塞操作（例如读写 Flash、等待串口应答），否则整个界面会卡住。正确做法是发送命令给业务任务，结果返回后再更新界面。

5. 界面与业务分离

界面代码最容易变成“业务逻辑、通信协议、控件操作混在一起”的状态。推荐的分层：

业务层（任务 / 状态机）   只关心数据和命令，不包含任何 lv_ 调用
      │  数据更新消息 ↓        ↑ 用户命令消息
界面适配层（GUI 任务内）   把数据转换成控件更新；把控件事件转换成命令
      │
LVGL 控件（页面）          只负责显示和交互

LVGL v9 提供了观察者（Observer）机制，可以把控件直接绑定到一个“主题”（subject）上，数据变化时控件自动更新：

static lv_subject_t temp_subject;

void ui_bind_init(void)
{
    lv_subject_init_int(&temp_subject, 0);
    lv_label_bind_text(temp_label, &temp_subject, "%d °C");   /* 标签自动跟随数值 */
}

/* GUI 任务收到数据更新消息后 */
void ui_on_temperature(int value)
{
    lv_subject_set_int(&temp_subject, value);
}

这样业务层只需要发送“温度变为 25”这样的数据消息，不需要知道界面上有哪些控件在显示它。

6. 多页面管理

  • 按需创建：每个页面提供 page_xxx_create() 和 page_xxx_destroy()，切换时创建新页面、删除旧页面，内存占用只取决于当前页面。
  • 常驻页面：频繁切换且创建开销大的页面可以常驻，切换时用 lv_obj_add_flag(obj, LV_OBJ_FLAG_HIDDEN) 隐藏。
  • 屏幕切换动画：lv_screen_load_anim(new_scr, LV_SCR_LOAD_ANIM_FADE_IN, 200, 0, true)，最后一个参数为 true 时自动删除旧屏幕。
  • 页面删除后，业务层不能再持有其中控件的指针，否则会访问已释放的内存，这是 LVGL 项目中常见的崩溃原因。

7. 工作场景：一个设备参数显示与设置界面

需求：800×480 触摸屏，主页显示 6 个实时参数，设置页可修改报警阈值，数据来自 Modbus 通信任务。

  1. 设计规范：先定义颜色、字号、间距和卡片样式，所有页面共用。
  2. 页面结构：主页 Grid 布局 3×2 卡片；设置页使用列表 + 数字键盘；顶部状态栏常驻显示通信状态和时间。
  3. 数据流：通信任务解析数据后发送消息给 GUI 任务，GUI 任务更新 subject；设置页确认后发送“写参数”命令给业务任务，结果返回后提示成功或失败。
  4. 防误操作：写入过程中禁用确认按钮，超时提示失败并恢复。
  5. 验证：反复切换页面 1000 次检查内存；通信中断时界面显示离线状态而不是停留在旧数据。

8. 界面开发检查清单

  • 布局是否使用 Flex / Grid 和百分比尺寸，而不是写死坐标。
  • 样式变量是否为静态或全局，颜色和尺寸是否集中定义。
  • 事件回调中是否避免了耗时和阻塞操作。
  • 业务层是否与 LVGL 调用分离，数据通过消息或 subject 传递。
  • 页面删除后是否没有残留的控件指针被使用。
  • 通信中断、数据异常等状态在界面上是否有明确显示。
  • 是否长时间反复切换页面验证内存稳定。
