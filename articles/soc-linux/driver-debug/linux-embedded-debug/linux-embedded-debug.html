嵌入式 Linux 驱动与系统调试

嵌入式 Linux 调试通常横跨内核.设备树.驱动.用户态程序.文件系统和启动脚本。本文按工程排错视角整理常见入口：串口日志.dmesg.设备树.设备节点.sysfs/procfs.内核模块.交叉编译和 gdbserver。

调嵌入式 Linux 不要一上来就改代码。先确认硬件连线.设备树是否生效.驱动是否匹配.设备节点是否创建.权限是否正确.用户程序打开路径是否正确。

1.启动日志与串口控制台

串口日志是嵌入式 Linux 最重要的第一现场。U-Boot.内核启动.驱动 probe.rootfs 挂载.systemd 启动都可以从串口看到线索。 

dmesg
cat /proc/cmdline
cat /proc/version
uname -a

如果系统无法启动，优先保留完整串口日志；如果系统已经启动，优先用 dmesg 查看内核日志。

2.设备树调试

设备树描述硬件资源，例如 GPIO.I2C.SPI.UART.中断.时钟.电源和 pinctrl。驱动能否 probe 成功，很多时候取决于设备树节点是否正确。 

ls /proc/device-tree
find /proc/device-tree -name "*spi*"
hexdump -C /proc/device-tree/model

常见问题包括 compatible 不匹配.pinctrl 未配置.GPIO 极性错误.中断号错误.status 没有设为 okay。

3.驱动 probe 与 dmesg

驱动加载后会根据 compatible.总线类型或设备 ID 匹配设备。匹配成功后执行 probe。probe 失败时，通常会在 dmesg 中留下错误码。

dmesg | grep -i spi
dmesg | grep -i i2c
dmesg | grep -i error

如果用户态找不到设备，先确认驱动是否 probe，再确认设备节点是否创建，最后确认权限和应用路径。

4.设备节点与 sysfs

Linux 中很多设备会在 /dev 下生成节点，例如串口.SPI.I2C.输入设备等。/sys 则可以查看设备.驱动.总线和类的关系。

ls -l /dev/ttyS*
ls -l /dev/spidev*
ls /sys/class
ls /sys/bus/platform/devices
ls /sys/bus/spi/devices

5.内核模块

如果驱动编译成模块，可以使用 insmod.rmmod.lsmod 调试加载和卸载。

insmod my_driver.ko
lsmod
rmmod my_driver
dmesg | tail -n 80

模块加载失败时，要检查内核版本.符号依赖.设备树匹配和模块参数。

6.交叉编译与部署

嵌入式 Linux 用户程序通常在 PC 上交叉编译，再拷贝到板子运行。常见问题是工具链架构不匹配.动态库缺失.运行权限不够。

file app
readelf -h app
ldd app
scp app root@192.168.1.10:/opt/app/

如果目标板没有 ldd，可以用 readelf -d 查看依赖库。

7.用户态调试：strace 与 gdbserver

strace 用来跟踪系统调用，gdbserver 用来远程调试程序。文件打不开.设备打不开.权限问题，优先用 strace；崩溃和逻辑错误，可以用 gdbserver。

strace -o trace.log ./app

gdbserver :2345 ./app
# PC 端：
# target remote 192.168.1.10:2345

9.工程检查清单

  • 设备树节点是否实际进入运行系统。
  • compatible 是否和驱动匹配。
  • dmesg 中是否有 probe 成功或失败信息。
  • 设备节点是否创建，权限是否正确。
  • 用户程序打开路径是否与设备节点一致。
  • 应用架构和动态库是否匹配目标板。
  • 问题是否能通过 strace.gdbserver 或串口日志复现。
