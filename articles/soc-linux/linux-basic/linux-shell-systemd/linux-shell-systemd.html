Linux Shell 脚本与 systemd 服务

Linux 工程中，Shell 脚本经常用于自动构建.部署.启动.日志收集和环境检查。systemd 则常用于把应用程序做成系统服务，实现开机自启.异常重启.日志统一管理和依赖控制。

1.Shell 脚本基础结构

#!/bin/sh

APP_DIR=/opt/app
APP_BIN=$APP_DIR/app

if [ ! -x "$APP_BIN" ]; then
    echo "app not executable: $APP_BIN"
    exit 1
fi

exec "$APP_BIN"

嵌入式系统里常见的是 BusyBox sh，不一定支持完整 Bash 语法。脚本如果要在裁剪系统里运行，建议优先写 POSIX sh 风格。

2.变量与引号

Shell 中变量替换和空格处理非常容易出错。路径变量建议始终加双引号，避免路径中出现空格或空值导致命令行为异常。 

LOG_DIR="/var/log/my app"
mkdir -p "$LOG_DIR"

echo "log dir: $LOG_DIR"

3.条件判断与循环

if [ -f /etc/os-release ]; then
    cat /etc/os-release
fi

for dev in /dev/ttyS*; do
    echo "found serial: $dev"
done

while true; do
    date
    sleep 1
done

脚本里不要写没有退出条件的死循环，除非它本来就是守护脚本；即便是守护脚本，也要考虑日志大小.异常退出和信号处理。

4.重定向与日志

./app > app.log 2>&1
./app >> app.log 2>&1

tail -f app.log

stdout 是标准输出，stderr 是标准错误。2>&1 表示把错误输出也重定向到标准输出。嵌入式设备要注意日志文件大小，避免写满 Flash。

5.set -e 与错误处理

set -e 可以让脚本在命令失败时退出，但它并不是万能的。复杂脚本建议对关键命令显式检查返回值。 

if ! cp app /usr/bin/app; then
    echo "copy app failed"
    exit 1
fi

6.systemd 服务文件

在带 systemd 的 Linux 系统中，可以把应用做成服务。这样可以实现开机启动.异常重启.统一日志和依赖管理。 

[Unit]
Description=My Embedded App
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/app
ExecStart=/opt/app/app
Restart=always
RestartSec=2

[Install]
WantedBy=multi-user.target

保存为 /etc/systemd/system/myapp.service 后，可以启用服务：

systemctl daemon-reload
systemctl enable myapp
systemctl start myapp
systemctl status myapp

7.journalctl 查看日志

journalctl -u myapp -f
journalctl -u myapp --since "1 hour ago"
journalctl -xe

如果程序通过 systemd 启动，标准输出和标准错误通常会进入 journal。现场排查时，journalctl -u 服务名 -f 非常常用。

8.crontab 与定时任务

crontab -e

# 每天凌晨 3 点执行日志清理
0 3 * * * /opt/app/clean_log.sh

对于周期性维护任务，crontab 很简单；对于长期运行的服务，systemd service 更合适。

9.嵌入式启动脚本建议

  • 启动前检查配置文件和可执行权限。
  • 日志路径要存在，并限制日志大小。
  • 脚本中使用绝对路径，减少环境变量依赖。
  • 启动失败要打印明确错误原因。
  • 可执行文件升级时，保留版本号和回滚路径。

10.工程检查清单

  • 脚本首行解释器是否存在。
  • 脚本是否有执行权限。
  • 路径变量是否加双引号。
  • 是否兼容 BusyBox sh。
  • systemd 服务是否设置 WorkingDirectory。
  • 服务异常退出后是否需要自动重启。
  • 日志是否可能写满 Flash。
