U-Boot 组成与构建流程

U-Boot 是嵌入式 Linux 系统中常见的 Bootloader。它的核心任务是完成最早期硬件初始化、加载内核镜像、加载设备树、准备启动参数，并最终跳转到 Linux Kernel 入口。

学 U-Boot 不要只记命令。要先理解启动链路：ROM Code → SPL/TPL → U-Boot proper → Kernel → RootFS。调板子时，任何一个环节出错，最终表现都可能是“系统起不来”。

一、U-Boot 在系统启动链路中的位置

SoC 上电后，最先运行的通常不是 U-Boot，而是芯片内部 ROM Code。ROM Code 根据启动介质选择规则，从 eMMC、SPI Flash、SD 卡、NAND、USB 等位置加载下一阶段程序。很多平台会先加载 SPL，再加载完整 U-Boot。

二、U-Boot 的主要职责

  • 初始化串口，输出早期启动日志。
  • 初始化 DDR、时钟、PMIC、存储控制器等关键硬件。
  • 从 Flash、eMMC、SD、TFTP 等位置加载内核镜像。
  • 加载设备树 DTB，并可对设备树做启动前修正。
  • 设置 Kernel 启动参数，例如 bootargs。
  • 提供命令行环境，方便烧录、调试、读写存储和网络启动。

三、U-Boot 源码目录

不同版本目录略有差异，但常见结构如下：

u-boot/
├── arch/              # 架构相关代码，如 arm、riscv
├── board/             # 板级代码
├── configs/           # defconfig 配置文件
├── drivers/           # 驱动代码
├── dts/               # U-Boot 使用的设备树
├── include/           # 头文件
├── common/            # 通用命令和启动逻辑
├── cmd/               # U-Boot 命令实现
├── env/               # 环境变量存储相关
└── Makefile

移植 U-Boot 时，最常修改的是板级目录、defconfig、设备树、DDR 初始化、存储启动配置和环境变量位置。

四、配置系统：defconfig 与 menuconfig

U-Boot 使用 Kconfig 配置系统。通常先选择板级 defconfig，再根据需要进入 menuconfig 修改功能。

make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- board_defconfig
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- menuconfig

常见配置包括启动命令、命令行功能、网络协议、存储驱动、文件系统支持、FIT 镜像支持、环境变量存储位置等。

五、交叉编译 U-Boot

构建 U-Boot 前要确认交叉工具链、板级 defconfig 和芯片厂商补丁是否匹配。

export ARCH=arm
export CROSS_COMPILE=arm-linux-gnueabihf-

make board_defconfig
make -j$(nproc)

64 位 ARM 平台通常使用 aarch64-linux-gnu- 工具链。具体前缀取决于芯片平台、厂商 SDK 和 ABI。

六、常见构建产物

  • u-boot.bin：裸二进制 U-Boot 镜像。
  • u-boot.elf：带符号信息的 ELF 文件，适合调试。
  • u-boot.img：带 U-Boot 镜像头的镜像。
  • u-boot.itb：FIT 镜像，可能包含多个镜像和签名。
  • SPL / u-boot-spl.bin：早期小体积加载阶段。

不同 SoC 对启动镜像格式要求不同，可能还需要厂商打包工具生成最终烧录镜像。

七、环境变量与 bootcmd

U-Boot 环境变量决定了从哪里加载内核、设备树和根文件系统。常见变量包括 bootcmd、bootargs、kernel_addr_r、fdt_addr_r。

printenv
setenv bootargs console=ttyS0,115200 root=/dev/mmcblk0p2 rw rootwait
saveenv
boot

调试启动失败时，重点查看 bootargs 是否正确、内核和 dtb 是否加载到正确地址、rootfs 路径是否匹配实际分区。

八、U-Boot 调试检查清单

  • 串口波特率和串口号是否正确。
  • DDR 初始化是否通过，内存容量是否识别正确。
  • 启动介质偏移和镜像格式是否符合 SoC 要求。
  • defconfig 是否对应当前板卡。
  • 设备树是否和板级硬件一致。
  • bootargs 中 rootfs 分区是否正确。
  • 内核镜像、dtb、rootfs 是否版本匹配。
