Linux 基础命令与文件系统

本文整理 Linux 入门和嵌入式 Linux 调试中最常用的基础命令与文件系统知识。重点不是背命令，而是理解 Linux 中“一切皆文件”的思想：普通文件、目录、设备节点、进程信息、内核参数，都可以通过统一的文件接口进行查看和操作。

嵌入式 Linux 调试时，很多问题不是代码本身，而是路径、权限、设备节点、挂载点、脚本执行环境和文件系统状态出错。先熟悉基础命令和目录结构，后面看驱动、进程和系统服务会轻松很多。

一、Linux 目录结构

Linux 没有 Windows 那种 C 盘、D 盘概念，所有内容都挂在根目录 / 下面。不同目录有不同职责。

  • /bin、/sbin：基础命令。
  • /etc：配置文件。
  • /dev：设备节点，例如串口、磁盘、GPIO 相关设备。
  • /proc：进程和内核运行时信息。
  • /sys：设备模型、驱动、总线、类等信息。
  • /mnt、/media：挂载外部存储或临时文件系统。

二、常用查看命令

日常定位问题时，先看文件、路径、权限和内容是否正确。 

pwd                 # 查看当前路径
ls -lah             # 查看文件和权限
cat file.txt        # 输出文本文件
head -n 20 log.txt  # 查看文件前 20 行
tail -f app.log     # 实时跟踪日志
du -sh *            # 查看当前目录下各项大小
df -h               # 查看磁盘/分区挂载和空间

三、搜索与过滤

Linux 调试经常需要在大量日志和源码中查找关键字。常用组合是 grep、find、xargs。 

grep -rn "error" .
find . -name "*.c"
find . -name "*.log" -mtime -1
ps aux | grep app
cat /proc/cpuinfo | grep Hardware

在嵌入式板子上，如果没有完整 GNU 工具，BusyBox 版本命令可能参数较少，需要根据实际系统裁剪情况调整写法。

四、权限与用户

Linux 文件权限分为所有者、所属组和其它用户三类，每类有读、写、执行权限。很多“命令不能执行”“设备打不开”的问题，本质是权限不对。 

chmod +x run.sh
chmod 755 app
chown root:root app
ls -l /dev/ttyS0

对脚本来说，只有读权限不够，还需要执行权限；对设备节点来说，应用程序还需要具备访问该设备节点的权限。

五、软链接与硬链接

软链接类似快捷方式，保存的是目标路径；硬链接是多个文件名指向同一个 inode。嵌入式系统里常用软链接管理版本、库文件和启动脚本。 

ln -s app_v1.2.0 app_current
ls -l app_current

如果移动了软链接指向的目标文件，软链接可能失效。排查程序找不到动态库时，也要检查软链接是否正确。

六、压缩、传输与同步

tar -czf project.tar.gz project/
tar -xzf project.tar.gz
scp app root@192.168.1.10:/usr/bin/
rsync -avz ./build/ root@192.168.1.10:/opt/app/

嵌入式开发中，常用 scp 或 rsync 把可执行文件传到开发板，再通过 SSH 登录运行。频繁调试时，rsync 比重复全量拷贝更高效。

七、/proc 与 /sys

/proc 和 /sys 是理解 Linux 运行状态的窗口。它们看起来像文件系统，但很多内容并不是真实磁盘文件，而是内核导出的运行时信息。 

cat /proc/meminfo
cat /proc/interrupts
cat /proc/cmdline
cat /proc/mounts
ls /sys/class
ls /sys/bus/platform/devices

调试驱动、设备树、内存、CPU、中断、挂载点时，这两个目录非常重要。

八、工程检查清单

  • 程序路径是否正确。
  • 脚本是否有执行权限。
  • 设备节点是否存在，权限是否允许访问。
  • 文件系统是否只读挂载。
  • 动态库软链接是否正确。
  • 日志路径所在分区是否有剩余空间。
  • BusyBox 命令是否支持你使用的参数。
