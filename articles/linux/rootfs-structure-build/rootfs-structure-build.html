根文件系统组成与构建流程

根文件系统 RootFS 是 Linux 启动后挂载的第一个文件系统，里面包含用户态程序、动态库、配置文件、设备节点、启动脚本和应用程序。Kernel 启动成功后，如果无法挂载 rootfs 或找不到 init，系统仍然无法进入用户态。

U-Boot 负责加载 Kernel，Kernel 负责驱动硬件和挂载 RootFS，RootFS 负责提供用户态环境。三者版本、路径、启动参数必须匹配，否则系统会卡在启动阶段。

一、RootFS 在启动链路中的作用

Kernel 根据启动参数中的 root= 找到根文件系统，挂载后执行第一个用户态程序，常见是 /sbin/init、/init 或 systemd。

二、RootFS 基本目录结构

rootfs/
├── bin/        # 基础用户命令
├── sbin/       # 系统管理命令
├── etc/        # 配置文件和启动脚本
├── lib/        # 动态库
├── usr/        # 用户程序和库
├── dev/        # 设备节点
├── proc/       # procfs 挂载点
├── sys/        # sysfs 挂载点
├── tmp/        # 临时目录
├── var/        # 日志、运行时数据
└── home/       # 用户目录

最小 rootfs 可以非常小，只需要 BusyBox、必要动态库、init 脚本和几个挂载点。完整发行版 rootfs 则会包含包管理器、systemd、网络工具、调试工具等。

三、BusyBox 根文件系统

BusyBox 把大量常用 Linux 命令集成到一个可执行文件中，非常适合资源有限的嵌入式系统。

make menuconfig
make -j$(nproc)
make CONFIG_PREFIX=$PWD/rootfs install

安装后，BusyBox 会在 bin、sbin 等目录下创建大量指向 busybox 的软链接，例如 ls、cat、sh。

四、动态库与链接器

如果用户程序是动态链接的，rootfs 中必须包含对应架构的动态库和动态链接器。否则即使文件存在，也可能运行时报 “not found”。

file app
readelf -l app | grep interpreter
readelf -d app | grep NEEDED

典型问题是：应用是 ARM64 架构，但 rootfs 里缺少 /lib/ld-linux-aarch64.so.1 或依赖库版本不匹配。

五、init 与启动脚本

Kernel 挂载 rootfs 后会尝试启动 init。BusyBox 系统常用 /etc/inittab 和 /etc/init.d/rcS，systemd 系统则启动 /sbin/init 指向 systemd。

::sysinit:/etc/init.d/rcS
::respawn:-/bin/sh
::ctrlaltdel:/sbin/reboot

最小系统中，rcS 通常负责挂载 proc、sysfs、devtmpfs，配置网络，启动应用。

六、挂载 proc、sysfs、devtmpfs

mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs none /dev
mount -t tmpfs none /tmp

如果这些伪文件系统没有挂载，很多命令和服务会异常，例如看不到进程信息、设备节点不完整、系统服务启动失败。

七、使用 Buildroot 构建 RootFS

Buildroot 可以自动构建交叉工具链、Bootloader、Kernel、RootFS 和用户态软件包，适合快速生成嵌入式 Linux 系统。

make menuconfig
make -j$(nproc)

Buildroot 常见产物位于 output/images，包括 rootfs.ext4、rootfs.tar、Image、dtb 等，具体取决于配置。

八、使用 Ubuntu Base 构建 RootFS

如果板子资源足够，也可以使用 Ubuntu Base 这类发行版根文件系统。它的优点是软件生态完整，缺点是体积更大、启动更慢、依赖更多。

tar -xpf ubuntu-base-xx.xx-base-arm64.tar.gz -C rootfs
cp /usr/bin/qemu-aarch64-static rootfs/usr/bin/
chroot rootfs /bin/bash

进入 chroot 后可以安装软件包、配置用户、网络、systemd 服务等。构建完成后再打包成 ext4、tar 或其它格式。

九、RootFS 打包格式

  • rootfs.tar：适合部署到已有分区。
  • rootfs.ext4：适合直接烧录到 ext4 分区。
  • cpio.gz：常用于 initramfs。
  • squashfs：只读压缩文件系统，适合固件镜像。
  • ubifs：适合 NAND Flash。

十、RootFS 启动问题排查

现象优先排查方向
Kernel panic: unable to mount root fsroot= 参数、分区、文件系统驱动、rootwait
No init found/sbin/init、/init、BusyBox 安装、执行权限
app: not found架构不匹配、动态链接器缺失、依赖库缺失
设备节点缺失devtmpfs、mdev/udev、驱动是否 probe
系统只读挂载参数、分区损坏、只读文件系统设计

十一、工程检查清单

  • rootfs 架构是否和 Kernel/应用一致。
  • 动态库和动态链接器是否完整。
  • /sbin/init 或 /init 是否存在且可执行。
  • /proc、/sys、/dev 挂载点是否存在。
  • U-Boot 的 bootargs 中 root= 是否匹配实际分区。
  • rootfs 打包格式是否符合启动介质和内核配置。
  • 日志目录是否可写，是否会写满 Flash。
