ARM Cortex-M3 与 Cortex-M4 架构详解

Cortex-M3 和 Cortex-M4 是 ARM 公司面向微控制器领域推出的两款经典处理器内核，被广泛应用于 STM32.TI MSP432.NXP LPC.瑞萨 RA 等系列芯片。理解这两款内核的架构细节，是掌握各类 ARM Cortex-M MCU 的基础。本文以 ARMv7-M Architecture Reference Manual 为主要参考，结合 Cortex-M3/M4 Technical Reference Manual，重点整理内核结构.寄存器模型.运行模式.存储映射.中断机制等核心知识点。

学习 ARM 架构不要死记架构手册的每一页。重点理解：处理器内核与芯片外设是两个独立层次——ARM 提供内核设计（CoreLand），芯片厂商在此基础上集成自己的外设（CoreSight 调试系统.STM32 的 GPIO/Timer/UART 等）。调 MCU 时遇到问题，往往需要从这两个层次分别排查。

1.ARM 架构版本与 Cortex-M 系列定位

在 ARM 架构体系中，架构版本用 "ARMvN" 表示（如 ARMv6.ARMv7.ARMv8），每一代架构定义了不同的指令集和功能特性。Cortex-M 系列是 ARM 针对微控制器（MCU）场景设计的处理器内核，采用的是 ARMv6-M（Cortex-M0.M0+.M1）和 ARMv7-M（Cortex-M3.M4.M7）架构。

下表展示 Cortex-M 主流内核的架构归属与基本定位：

内核架构版本指令集主要应用场景FPUMPU
Cortex-M0ARMv6-MThumb（基础子集）低功耗简单 MCU无可选
Cortex-M0+ARMv6-MThumb（基础子集）低功耗 MCU，入门级无可选
Cortex-M3ARMv7-MThumb-2（完整）通用 MCU，主流选择无可选
Cortex-M4ARMv7-MThumb-2 + DSP数字信号处理 MCU可选（FPv4）可选
Cortex-M7ARMv7-MThumb-2 + DSP + 半精度浮点高性能 MCU/MPU可选（FPv5）可选

Cortex-M3 是首个采用 ARMv7-M 架构的内核，引入了完整的 Thumb-2 指令集（混合 16/32 位指令），兼顾代码密度和执行效率。Cortex-M4 在 M3 基础上增加了 DSP 指令集和可选的 FPU，适合需要信号处理能力的场景。

本文重点围绕 Cortex-M3 和 Cortex-M4 展开。两者共享 ARMv7-M 架构，因此很多机制（如异常模型.寄存器组织）是完全相同的，差异主要集中在 DSP 指令和 FPU 部分。

2.寄存器模型

2.1 通用寄存器 R0~R15

Cortex-M 处理器有 16 个 32 位通用寄存器，功能分工如下：

寄存器别名功能说明
R0~R7—低位通用寄存器，所有 16 位和 32 位指令均可直接访问。用于函数参数传递（前四个参数通过 R0~R3 传递）.返回值（R0）.临时变量等。
R8~R12—高位通用寄存器。R8~R12 只有 32 位指令可以访问（无 16 位指令形式）。通常用作临时变量或保存中间结果。
R13SP（Stack Pointer）堆栈指针。实际有两个 SP：Main Stack Pointer（MSP）和 Process Stack Pointer（PSP）。复位后默认使用 MSP。SP 必须 4 字节对齐，违反对齐要求将触发 UsageFault。
R14LR（Link Register）链接寄存器。子程序调用（BL/BLX）时自动保存返回地址到 LR。函数返回时执行 BX LR 或 POP {..., PC}。异常返回时 LR 被特殊值覆盖。
R15PC（Program Counter）程序计数器。指向当前正在执行的指令地址。由于采用 Thumb 指令集（指令为 16/32 位混合），PC 的 bit[0] 必须为 1（表示 Thumb 态）。读取 PC 返回当前指令地址+4（流水线缘故）。

2.2 特殊寄存器

除通用寄存器外，Cortex-M 还有多个特殊寄存器（Special Registers），它们不在通用寄存器组中，需要通过 MRS/MSR 指令访问：

寄存器全称功能说明
PSPProcess Stack Pointer进程堆栈指针，用于线程模式下的堆栈。RTOS 中各任务切换时使用 PSP。
MSPMain Stack Pointer主堆栈指针。复位后默认使用。异常（中断）处理始终使用 MSP。
PRIMASKPriority Mask Register优先级掩码寄存器。bit[0] 置 1 时屏蔽所有可配置优先级的中断（NMI 和 HardFault 不可屏蔽）。用于保护关键代码段不被中断打断。
FAULTMASKFault Mask Register故障掩码寄存器。bit[0] 置 1 时屏蔽所有异常（包括 HardFault），只有 NMI 仍可响应。用于在故障处理时防止更高优先级异常干扰。
BASEPRIBase Priority Mask Register基础优先级掩码。设置为某个优先级值时，屏蔽所有优先级数值大于（等于或更低）该值的中断。优先级数值越大表示优先级越低。设为 0 表示不屏蔽任何中断。
CONTROLControl Register控制寄存器。bit[0] 选择使用 PSP（1）还是 MSP（0）。bit[1] 选择线程模式是特权级（0）还是用户级（1）。在用户级写入 CONTROL 会触发 HardFault。

2.3 xPSR（程序状态寄存器）

xPSR 是三个程序状态寄存器的合体，通过一个 32 位寄存器访问：

  • APSR（Application Program Status Register）：应用程序状态寄存器。保存 ALU 标志位：N（负数）.Z（零）.C（进位）.V（溢出）.Q（饱和标志，DSP 相关）。
  • IPSR（Interrupt Program Status Register）：中断程序状态寄存器。最低 9 位（ISR_NUMBER）表示当前正在执行的中断/异常编号（0 表示线程模式）。
  • EPSR（Execution Program Status Register）：执行程序状态寄存器。包含 ICI/IT 位（用于被打断的多寄存器加载/存储指令 LDM/STM）和 T 位（Thumb 状态，必须为 1，0 会触发 UsageFault）。

这三个寄存器合并为 xPSR，可以通过位域访问。通常不需要直接操作 xPSR，编译器工具链和 CMSIS 会自动处理。

3.运行模式与访问等级

3.1 两种运行模式

Cortex-M 处理器有两种运行模式：

  • Thread 模式（线程模式）：处理器执行普通应用程序代码。可以是特权级或非特权级。
  • Handler 模式（处理者模式）：处理器在处理异常/中断时进入此模式。始终是特权级。

复位后处理器进入 Thread 模式（特权级）。中断发生时进入 Handler 模式。中断返回后回到 Thread 模式。

3.2 特权等级

ARMv7-M 架构定义了两种访问等级：

  • Privileged（特权级）：可以访问所有资源，包括 NVIC.PCSRBASEPRI 等特权寄存器。在 Handler 模式下自动是特权级。
  • Unprivileged / User（用户级/非特权级）：对某些寄存器和指令有限制（例如无法操作 PRIMASK.FAULTMASK，无法使用 CPS 指令修改 PRIMASK/BASEPRI，无法访问系统定时器）。用于隔离不可信代码。

CONTROL 寄存器的 bit[0] 控制当前是特权级（0）还是用户级（1）。在用户级代码中写入 CONTROL 会触发 HardFault。

3.3 模式与特权等级的组合

Handler 模式Thread 模式
Privileged 特权级始终是特权级复位后默认状态
Unprivileged 用户级不存在（Handler 始终特权）可通过 CONTROL 设置
很多简单 MCU 应用不使用用户级/特权级区分，所有代码都运行在特权级。只有需要运行不可信第三方代码时（例如 OTA 升级中的未知来源固件），才需要配置 MPU 并切换到用户级。

4.存储映射与总线架构

4.1 预定义存储映射

ARMv7-M 采用预定义存储映射（Pre-defined Memory Map），4GB 地址空间被划分为多个固定区域：

地址范围大小区域名称说明
0x0000_0000 ~ 0x1FFF_FFFF512MBCode 区存放程序代码。可以执行（X）和读取。可作为 Flash 或 ROM。通常从 0x0800_0000（STM32 Flash）或 0x0020_0000（ITCM SRAM）开始。
0x2000_0000 ~ 0x3FFF_FFFF512MBSRAM 区存放数据。可执行。通常从 0x2000_0000 开始。部分芯片支持 SRAM 映射到 Code 区执行（ITCM/DTCM）。
0x4000_0000 ~ 0x5FFF_FFFF512MBPeripheral 区芯片外设寄存器（如 GPIO.Timer.UART）。只能通过 AHB-APB 总线访问，不能执行代码。
0x6000_0000 ~ 0x9FFF_FFFF1GB外部 RAM 区片外存储（如果芯片有外部存储接口）。
0xA000_0000 ~ 0xDFFF_FFFF1GB外部 Device 区片外外设。
0xE000_0000 ~ 0xE00F_FFFF1MBSystem 区（Private Peripheral Bus）内核私有外设：NVIC.SCB.SYSTICK.MPU（如果存在）。调试组件（DWT.ITM.ETM.TPIU）。
0xE010_0000 ~ 0xFFFF_FFFF~480MBVendor 保留区芯片厂商自定义用途。

4.2 总线接口

Cortex-M3/M4 内部有多个总线接口，分别连接不同外设：

  • I-Code 总线：连接 Code 区（Flash），用于取指令。32 位 AHB-Lite 接口。取指时优先使用此总线。
  • D-Code 总线：连接 Code 区，用于常量数据访问。32 位 AHB-Lite 接口。
  • System 总线：访问 SRAM 区和外设区。32 位 AHB-Lite 接口。
  • PPB（Private Peripheral Bus）：访问内核私有外设（NVIC.SCB.SYSTICK.MPU.调试组件）。

芯片厂商在此基础上构建自己的外设系统。例如 STM32 将外设挂载在 APB/AHB 总线上，并通过 AHB-to-APB 桥接器连接。注意外设区域不可执行代码，在此区域取指将触发 HardFault 或 BusFault。

4.3 位带操作（Bit-banding）

Cortex-M3/M4 支持位带操作，允许原子性地操作外设或 SRAM 中的单个位。位带机制将每个 bit 映射为一个 32 位字：

  • SRAM 位带别名区：0x2000_0000 ~ 0x200F_FFFF 中的每个 bit 对应 0x2200_0000 ~ 0x221F_FFFF 中的 32 位字。
  • 外设位带别名区：0x4000_0000 ~ 0x400F_FFFF 中的每个 bit 对应 0x4200_0000 ~ 0x421F_FFFF 中的 32 位字。

别名区计算公式：alias_address = 0x2200_0000 + (byte_offset × 32) + (bit_number × 4)。对位带别名地址的写入相当于原子地修改原地址对应 bit。

5.异常与中断机制

5.1 异常类型

ARMv7-M 架构定义了一套统一的异常模型，所有中断和故障都属于"异常"。异常编号如下（编号越小优先级越高）：

编号异常类型说明
1Reset复位。最高优先级，芯片上电或复位按钮触发。
2NMI不可屏蔽中断。通常由看门狗或电压检测器触发。优先级固定为 -2（仅次于 Reset）。
3HardFault硬件故障。所有其他故障处理不了的都会汇总到这里。优先级固定为 -1。
4MemManage存储管理故障。由 MPU 违规触发（例如用户级代码访问特权级资源.访问未对齐地址等）。
5BusFault总线故障。取指令或数据访问时总线返回错误（例如访问无效地址.取指失败）。
6UsageFault用法故障。未定义指令.非法状态切换（如在非 Thumb 态执行）.除零.切换到 ARM 态（尝试执行 BLX R14 等）等。
7~10—保留。
11SVCall系统服务调用。执行 SVC 指令触发，用于触发操作系统服务（如 FreRTOS 的 svc指令）。
12~13—保留。
14PendSV可挂起系统调用。用于 OS 任务切换，通常由软件设置挂起标志触发。优先级可配置（通常最低）。
15SysTick系统节拍定时器。OS 心跳或普通定时中断。优先级可配置。
16~255IRQ[0:239]外部中断。由芯片厂商定义，通常对应各外设中断（UART.TIM.GPIO 等）。

5.2 NVIC（嵌套向量中断控制器）

NVIC 是内核内置的中断控制器，负责管理所有外部中断（IRQ）和异常。NVIC 的主要特性：

  • 可编程优先级：每个中断有 8 位优先级字段（实际可用位数由芯片厂商决定，STM32 只使用高 4 位，因此只有 16 级可配置优先级，0~15）。数值越小优先级越高。
  • 嵌套支持：高优先级中断可以打断低优先级中断（如果使能了分组和优先级）。
  • 向量中断：中断响应时，硬件自动从向量表中取出处理函数地址并跳转，无需软件判断中断源。
  • 动态优先级修改：可以在运行时修改中断优先级。
  • 外部中断使能/除能：每个 IRQ 有独立的使能位（ISER/ICER）和挂起位（ISPR/ICPR）。

5.3 向量表

向量表存储在 Code 区起始位置（默认 0x0800_0000），每个异常/中断对应一个 32 位地址： 

地址偏移        异常编号    说明
0x0000_0000    —          MSP 初始值（栈指针）
0x0000_0004    1           Reset_Handler
0x0000_0008    2           NMI_Handler
0x0000_000C    3           HardFault_Handler
0x0000_0010    4           MemManage_Handler
0x0000_0014    5           BusFault_Handler
0x0000_0018    6           UsageFault_Handler
0x0000_0028    11          SVC_Handler
0x0000_0030    14          PendSV_Handler
0x0000_003C    15          SysTick_Handler
0x0000_0040    16          IRQ0_Handler（外设中断开始）
0x0000_0044    17          IRQ1_Handler
...

向量表位置可以通过 SCB->VTOR（Vector Table Offset Register）重新映射，支持将向量表放在 SRAM 中（用于 OTA 升级时动态切换启动固件）。VTOR 支持 5 位偏移对齐（32 字节对齐的倍数），部分芯片支持更细粒度。

5.4 中断响应流程

中断响应过程由硬件自动完成，无需软件介入：

  1. 中断到达 NVIC：NVIC 判断该中断优先级是否足够高到打断当前代码。
  2. 异常进入：处理器自动将 8 个寄存器压栈（xPSR.PC.LR.R12.R0~R3）。如果使用了 FPU，还要压栈 S0~S15 和 FPSCR（lazy stacking，见 5.6 节）。
  3. 取向量：从向量表中取出该异常的处理函数地址。
  4. 跳转到处理函数：PC 指向异常处理函数，LR 被自动设置为 EXC_RETURN 值（见 5.5 节）。
  5. 执行异常处理：在 Handler 中执行外设的中断服务程序（ISR）。
  6. 异常返回：执行 bx LR 或 POP {..., PC}，LR 中的 EXC_RETURN 值触发异常返回序列。
  7. 恢复现场：处理器从栈中恢复寄存器，继续执行被中断的代码。

5.5 EXC_RETURN（异常返回）

EXC_RETURN 是 LR 在异常时被自动设置的特殊值，用于指示异常返回后应该使用哪个堆栈和哪个处理器模式：

EXC_RETURN 值含义
0xFFFF_FFF1返回后使用 MSP，退出 Handler 模式，进入线程模式（特权级）
0xFFFF_FFF9返回后使用 MSP，退出 Handler 模式，进入线程模式（特权级）
0xFFFF_FFFD返回后使用 PSP，退出 Handler 模式，进入线程模式（特权级）
0xFFFF_FFF5返回后使用 MSP，退出 Handler 模式，进入线程模式（非特权级，已废弃）
0xFFFF_FFED返回后使用 PSP，退出 Handler 模式，进入线程模式（非特权级）

实际开发中最常见的是 0xFFFF_FFF1（裸机程序，返回后使用 MSP）和 0xFFFF_FFF9（RTOS 中中断返回后使用 PSP）。执行以 EXC_RETURN 值为目标的 BX 或 POP 操作时，处理器识别这是一个异常返回，而不是普通函数调用。

5.6 咬尾中断（Tail-chaining）

这是 ARMv7-M 架构中一个重要的中断优化机制，用于减少连续中断处理的开销。

没有咬尾中断时的处理流程：假设处理器正在处理一个中断（A），此时另一个更高优先级的中断（B）到达并被挂起。中断 A 处理完成后，正常流程是：

  1. 中断 A 完成，执行返回，恢复寄存器。
  2. 检测到 B 挂起，再次压栈 8 个寄存器。
  3. 跳转到 B 处理函数。

这里存在两次栈操作（一次弹出恢复，一次压栈保存），浪费了约 12 个时钟周期。

咬尾中断的工作方式：当处理器在处理中断 A 时，B 到达并挂起。中断 A 处理完成后，不执行寄存器恢复（弹出），而是直接跳转到中断 B 的处理函数。此时处理器：

  1. 中断 A 完成，不恢复寄存器（跳过栈弹出）。
  2. 直接跳转到 B 的处理函数（省去了重新压栈的 8 个寄存器操作）。
  3. B 处理完成后，才统一恢复所有寄存器。

咬尾中断消除了连续中断之间的寄存器弹栈和压栈开销，将两次中断处理之间的间隔从约 24 个时钟周期缩短到约 6 个周期。典型嵌入式场景（多个高频外设中断）下，这个优化效果显著。

5.7 晚到中断（Late-arriving）

晚到中断是另一个优化机制。当处理器正在压栈（即还在响应第一个中断的过程中）时，如果更高优先级的中断到达，处理器会：

  1. 立即处理这个更高优先级的中断（跳转到其处理函数）。
  2. 之后处理原先已经开始压栈的那个中断。

晚到中断机制进一步缩短了高优先级中断的响应时间，因为它避免了低优先级中断已经开始处理后才到达的高优先级中断的等待。

5.8 中断响应时间与中断延迟

中断延迟定义为从中断请求信号到达处理器到开始执行中断处理函数第一条指令的时间。ARMv7-M 的中断延迟指标：

  • 最小中断延迟：12 个时钟周期（从中断请求到开始取向量）。
  • 典型中断延迟：约 15~20 个周期（包括总线仲裁.优先级判断等）。
  • 最坏情况中断延迟：当处理器正在执行被中断屏蔽的更高优先级中断时，低优先级中断需要等到高优先级中断完成。

中断延迟的影响因素：

  • 指令流水线的深度：Cortex-M3/M4 采用 3 级流水线，中断响应需要插入流水线刷新周期。
  • 总线周期：栈操作需要访问 SRAM，SRAM 速度影响压栈时间。
  • 优先级反转：如果当前中断被高优先级中断打断，实际响应时间更长。
  • FPU lazy stacking：如果使能了 FPU 且中断使用浮点寄存器，lazy stacking 机制会在第一次使用 FPU 时才压栈浮点上下文，增加中断响应时间。

实际工程中，中断延迟通常以 MHz 为单位计算。以 72MHz 的 STM32F103 为例，最小中断延迟约 12/72MHz ≈ 167ns。但考虑到外设到达 NVIC 的路径延迟（外设时钟.APB 总线时钟.PRQ 同步等），整体中断响应时间通常在 500ns~1us 量级。

5.9 优先级分组与抢占

ARMv7-M 支持可编程优先级分组。当多个中断同时到达时，优先级决定处理顺序；更高优先级的中断可以打断正在处理的低优先级中断（嵌套）。

STM32 使用 4 位优先级字段（0~15），实际实现中将这 4 位分为两部分：抢占优先级（pre-emption priority）和子优先级（subpriority）。通过 AIRCR（应用程序中断和复位控制寄存器）的 PRIGROUP 字段配置分组方式：

...............

实际上 STM32 只实现了 4 位，因此只有 PRIGROUP 为 3 时才有意义（即全部 4 位作为抢占优先级，无子优先级）。这也是为什么很多 STM32 代码只用优先级数值判断谁打断谁。

6.Cortex-M4 独有特性：DSP 指令与 FPU

6.1 DSP 指令扩展

Cortex-M4 的一个核心差异是增加了 DSP 指令扩展，这些指令主要用于加速信号处理算法（如滤波.FFT.音频处理）。DSP 扩展基于 SIMD（Single Instruction Multiple Data）思想，单条指令可以同时处理多个数据元素：

  • 乘法累加（MAC）指令：SMLAD.SMLSD.SMMLA.SMMUL 等。单条指令完成乘加或乘减操作，广泛用于滤波器（FIR.IIR）的系数计算。典型滤波公式 y[n] = Σ h[k] * x[n-k] 可以直接用 MAC 指令高效实现。
  • SIMD（单指令多数据）指令：一次操作多个数据。例如 PKHBT.PKHTB 进行半字（16 位）打包/拆包，SADD8.SADD16 同时进行多组 8 位/16 位加法，SSAX 同时进行加法和减法（交叉相减）。
  • 饱和运算指令：SSAT（有符号饱和）.USAT（无符号饱和）将结果饱和到指定位宽，防止溢出。在音频处理.自动增益控制等场景非常有用。
  • 位操作指令：RBIT（位反转）.REV.REV16.CLZ（前导零计数）等，用于位反转排序.字节序转换.快速对数计算。
  • 乘-累加-移位指令：SMLAW.SMUWB 等，用于在滤波器中实现分数增益。

以一个简单的有限冲击响应滤波器（FIR）为例，传统 C 代码计算一个输出样本需要 N 次乘法和 N-1 次加法循环。使用 M4 的 MAC 指令，每个样本只需要 N/4 条 SIMD MAC 指令（假设使用 32 位指令同时处理 2 个 16 位数据）。以 16 阶 FIR 滤波器为例，计算量减少约 4 倍。

6.2 FPU（浮点单元）

Cortex-M4 可选集成 FPU，通过 CP10 和 CP11 协处理器访问，符合 ARMv7-M 的 FPv4-SP（单精度）扩展规范：

  • 32 位单精度浮点：符合 IEEE 754 单精度标准，尾数 23 位，指数 8 位，约 7 位十进制有效数字。
  • 专用浮点寄存器：S0~S31（共 32 个 32 位寄存器），每个可存放一个单精度浮点数。注意 D0~D31 是 S0~S31 的别名（每两个 S 寄存器组成一个 D 寄存器），用于双精度指令。
  • 浮点上下文：浮点寄存器组（S0~S31）和 FPSCR（Floating-point Status Control Register）构成浮点上下文，切换时需要保存.恢复。
  • 硬件加速：浮点加减乘除.比较.开方.平方根.绝对值.取反.定点互转均有硬件指令支持。
  • 半精度扩展（仅 FPv5 的 M7 支持）：Cortex-M4 的 FPU 不支持半精度（16 位）浮点。

如果 M4 芯片没有 FPU（如 STM32F4 基础系列），浮点运算由软件模拟（软浮点），效率很低。选型时需要注意芯片后缀：STM32F407 有 FPU（FPU 使能），而 STM32F407 某些型号可能不带。可以通过 SCB_CPUID 或读取 CPACR 寄存器判断是否有 FPU。

启用 FPU 后，编译器会在浮点运算代码段自动使用 FPU 指令（需要使用 -mfloat-abi=hard 编译选项）。如果链接了软浮点库但芯片没有 FPU，程序会跑飞或进入 HardFault。IDE/工具链配置必须与实际硬件匹配。

7.MPU（内存保护单元）

MPU（Memory Protection Unit）是可选的内存保护组件，Cortex-M3/M4 均支持。通过配置 MPU，可以将地址空间划分为多个区域，并为每个区域定义访问权限：

  • 区域数量：MPU 最多支持 8 个区域（编号 0~7），区域可以重叠（编号大的优先）。
  • 区域大小：最小 32 字节，最大 4GB，必须是 2 的整数次幂。实际常用大小从 32B.64B.128B...到 4GB。
  • 访问权限：可配置为特权级读写/只读/不可访问，用户级读写/只读/不可访问。
  • 缓存策略：可配置为强顺序（Strongly-ordered）.设备内存（Device）.普通内存（Normal）。
  • 子区域禁止：可以将一个区域划分为 8 个子区域，独立禁止其中某些子区域，实现细粒度覆盖。这常用于将大块内存中的特定地址排除在某个区域之外。

MPU 配置示例（使用 CMSIS）： 

MPU->RNR  = 0;                    // 选择区域 0
MPU->RBAR = 0x20000000             // 基地址
          | MPU_REGION_VALID
          | 0;                      // 区域编号
MPU->RASR = MPU_REGION_SIZE_64KB   // 64KB 大小
          | MPU_AP_FULL_ACCESS     // 特权级和用户级均可读写
          | MPU_REGION_ENABLE;     // 使能该区域

MPU->CTRL = MPU_CTRL_ENABLE_Msk    // 使能 MPU
           | MPU_CTRL_PRIVDEFENA_Msk; // 特权级可访问未定义区域

对于 RTOS 系统，通常用 MPU 隔离各任务堆栈，防止一个任务越界写到另一个任务的内存。例如可以为每个任务分配独立的内存区域并设置为只读（防止其他任务篡改），或者将任务栈设置为不可执行（防止代码注入）。

8.调试架构

8.1 调试接口

Cortex-M3/M4 支持两种调试接口：

  • JTAG：传统的 4/5 线调试接口（TDI.TDO.TMS.TCK，可选 TRST）。可以同时访问多个 TAP（Test Access Port）。引脚占用多，但支持边界扫描等功能。
  • SWD（Serial Wire Debug）：ARM 推出的两线调试接口（SWDIO.SWCLK），仅需两根信号线。STM32 系列默认使用 SWD。SWD 还支持 SWO（Serial Wire Output）用于 ITM 追踪。

两种接口可以通过相关寄存器（DBGMCU_CR）切换。实际芯片调试引脚（如 PA13.PA14.SWCLK.SWDIO）由芯片厂商定义。部分芯片支持同时使用 JTAG 和 SWD（但引脚不能复用）。

8.2 调试组件

内核内置多个调试组件，通过 PPB（Private Peripheral Bus）访问：

  • DWT（Data Watchpoint and Trace）：数据观察点和跟踪单元。支持最多 4 个观察点（触发暂停或数据追踪）和性能计数器。DWT 可以监视特定内存地址的访问（读/写/读+写），访问发生时触发调试事件。
  • ITM（Instrumentation Trace Macrocell）：跟踪宏单元。软件可以通过向 ITM 寄存器写入数据，数据通过 SWO 输出到调试器。ITM 支持 32 个通道，通道 0 用于 printf 重定向，通道 31 用于 RTOS 追踪。相比 UART，ITM 输出更实时且不影响实时性。
  • FPB（Flash Patch and Breakpoint）：Flash 补丁和断点单元。最多支持 6 个指令断点（将某地址指令替换为 BKPT 指令）和 2 个常量补丁（将某地址读取重定向到另一个地址）。
  • TPIU（Trace Port Interface Unit）：追踪端口接口单元。将 DWT 和 ITM 的数据输出到外部追踪接口（SWO 或并行追踪端口）。

在实际调试中，断点由 FPB 实现；变量监视由 DWT 实现；printf 重定向到 ITM 是嵌入式调试中的常用技巧。

8.3 调试模式与低功耗

处理器进入睡眠模式时，调试连接仍然保持（因为调试组件由独立的调试时钟驱动）。但调试器无法暂停睡眠中的处理器——如果需要调试睡眠相关代码，需要配置 DWT 以在睡眠进入/退出时产生调试事件，或使用 WFI（Wait For Interrupt）指令调试。

9.SYSTICK 定时器

SysTick 是内核内置的 24 位倒计时定时器，常用于操作系统心跳（RTOS 的时间片调度）或普通延时.超时检测：

  • STK_CTRL（控制寄存器）：bit[0] ENABLE 使能定时器。bit[1] TICKINT 使能中断（计数器归零时触发 SysTick_Handler）。bit[2] CLKSOURCE 选择时钟源（0=HCLK/8，1=HCLK）。
  • STK_LOAD（重载值寄存器）：每次减到 0 后自动从该值重载。24 位宽，最大值 0x00FF_FFFF。
  • STK_VAL（当前值寄存器）：当前计数值，只读。写入任何值会清零计数器并清除 COUNTFLAG。
  • STK_CALIB（校准寄存器）：提供参考校准值 TENMS（10ms 对应的计数值），部分芯片未实现此值。

SysTick 的配置示例（10ms 中断，72MHz 时钟）： 

SysTick->LOAD  = 720000 - 1;      // 720000/72MHz = 10ms
SysTick->VAL   = 0;                 // 清零当前值
SysTick->CTRL  = SysTick_CTRL_CLKSOURCE_Msk  // HCLK 时钟
               | SysTick_CTRL_TICKINT_Msk    // 使能中断
               | SysTick_CTRL_ENABLE_Msk;    // 使能定时器

在 RTOS 中通常配置为 1ms 中断一次（10ms 或 1ms 取决于 OS 调度精度要求）。注意 SysTick 中断优先级在 NVIC 中可配置，默认优先级较低（通常为 15 或最低可配置优先级）。

11.工程实践要点

  • 工具链匹配：编译.链接.调试工具链必须与芯片内核匹配。Cortex-M3 用 armv7-m 架构，Cortex-M4（带 FPU）需要 armv7em 架构。Keil/IAR/GCC 都有对应配置项。
  • 中断优先级：STM32 使用 4 位（16 级），NXP LPC 可能用 3 位（8 级）。优先级数值越小优先级越高，与直觉相反，容易出错。
  • 堆栈对齐：SP 必须 4 字节对齐，违反将对齐要求将触发 UsageFault。中断压栈自动保证 8 字节对齐。
  • 堆栈配置：MSP 用于中断处理和系统级代码，PSP 用于用户任务（RTOS 环境）。裸机程序通常只用 MSP。
  • 位带操作：适合操作外设寄存器中的控制位，比读-改-写更安全（避免竞争）。
  • volatile 的使用：外设寄存器访问必须加 volatile，防止编译器优化掉访问或重排指令。
  • FPU lazy stacking：使能 FPU 后，中断处理时浮点寄存器不会立即压栈（节省中断响应时间），直到第一次使用 FPU 指令时才压栈。如果中断频繁调用浮点代码，lazy stacking 的首次调用会有额外开销。
  • 咬尾中断：在高频中断场景下，咬尾中断优化效果显著。设计中断优先级时，将可能连续触发的相关中断优先级设为相邻值，可以充分利用咬尾机制减少中断处理开销。
