MCU 调试接口与量产烧写

整理 SWD / JTAG 调试接口设计、调试器连不上的排查与救砖方法、SWO / RTT / 数据断点 / DWT 等调试手段、命令行烧录、量产烧录流程与唯一数据写入，以及产线测试固件的设计。

1. 调试接口：SWD 与 JTAG

ARM Cortex-M 芯片普遍支持两种调试接口：

对比SWDJTAG
信号线SWDIO、SWCLK（+ 可选 SWO、NRST）TMS、TCK、TDI、TDO（+ 可选 TRST、NRST）
引脚数2 根4~5 根
菊花链不支持支持多芯片串联
适用Cortex-M 首选，节省引脚多芯片调试、FPGA、部分非 ARM 芯片

硬件设计建议：

  • 预留 SWDIO、SWCLK、NRST、GND、VCC（参考电压），有条件再加 SWO（用于 printf 输出和性能分析）。NRST 能让调试器在芯片“锁死”时强制复位连接。
  • 使用标准接口座（如 2×5 1.27mm 的 Cortex Debug 接口），方便直接连接调试器；量产板可以只留测试点，由治具上的顶针连接。
  • VCC 引脚是给调试器做电平参考的，大多数调试器不会通过它给目标板供电，目标板需要自己上电。

2. 调试器连不上怎么办

现象常见原因解决方法
新板子完全连不上供电、复位电路、SWD 走线问题测量 VDD、NRST 电平；降低 SWD 时钟频率
以前能连，烧了某个程序后连不上程序把 SWD 引脚配置成了 GPIO，或很快进入了低功耗模式使用 Connect Under Reset：调试器在复位期间建立连接，抢在用户程序运行前停住 CPU
连接后马上断开程序频繁复位（看门狗、HardFault 后复位）Connect Under Reset，或拉高 BOOT0 从系统存储器启动后再擦除
提示芯片被保护开启了读保护解除读保护（会整片擦除），Level 2 则不可恢复
低功耗产品调试困难进入 Stop / Standby 后调试接口断开调试时开启“低功耗模式下保持调试连接”（STM32 的 DBGMCU 配置位）

避免把自己锁在外面：初始化代码中不要轻易把 PA13/PA14（STM32 的 SWD 引脚）复用为普通 GPIO；如果确实需要，就在上电后延时一两秒再切换，给调试器留出连接窗口，或者在软件中提供“进入调试模式”的方式。

3. 调试手段：断点之外

  • SWO / ITM 输出：通过 SWO 引脚输出 printf，不占用 UART，几乎不影响程序时序。Cortex-M3/M4/M7 支持，M0/M0+ 不支持。
  • RTT（SEGGER Real Time Transfer）：通过调试器读写 RAM 中的缓冲区实现双向通信，速度快、开销小，只需 SWD 两根线，J-Link 上使用非常方便。
  • 数据断点（Watchpoint）：当某个变量被写入时停下来，定位“谁改了我的变量”这类内存踩踏问题非常有效。
  • 实时查看变量：调试器在程序运行时读取 RAM（如 STM32CubeMonitor、J-Scope），适合观察控制环中的变量变化。注意不要实时读取“读清零”的寄存器。
  • 性能分析：用 DWT 周期计数器测量一段代码的执行时间，比用 GPIO 翻转配合示波器更方便。
/* Cortex-M3/M4/M7：使用 DWT 周期计数器测量执行时间 */
static inline void cycle_counter_init(void)
{
    CoreDebug->DEMCR |= CoreDebug_DEMCR_TRCENA_Msk;
    DWT->CYCCNT = 0;
    DWT->CTRL  |= DWT_CTRL_CYCCNTENA_Msk;
}

uint32_t t0 = DWT->CYCCNT;
filter_process(samples, n);
uint32_t cycles = DWT->CYCCNT - t0;          /* 主频 168MHz 时，cycles / 168 即为微秒数 */

4. 烧录方式一览

方式接口适用阶段
调试器烧录SWD / JTAG研发调试、小批量生产
系统 BootloaderUART、USB DFU、CAN、I2C（需拉 BOOT 引脚）无调试器的现场、生产线
自定义 Bootloader产品已有的通信接口产品交付后的升级
离线烧录器SWD，一键烧录，无需电脑量产，多工位并行
芯片预烧录由芯片代理商或烧录厂在贴片前烧录大批量生产

命令行工具让烧录可以脚本化，便于接入自动化测试和生产工具：

# STM32CubeProgrammer：擦除、烧录、校验、复位运行
STM32_Programmer_CLI -c port=SWD -e all -w app.hex -v -rst

# OpenOCD：通用调试器支持（ST-Link、CMSIS-DAP、J-Link 等）
openocd -f interface/cmsis-dap.cfg -f target/stm32f4x.cfg \
        -c "program app.elf verify reset exit"

# J-Link Commander 脚本
JLinkExe -device STM32F407VG -if SWD -speed 4000 -CommanderScript flash.jlink

5. 量产烧录流程

研发阶段“能烧进去”就行，量产要考虑效率、一致性和可追溯：

  1. 合并固件：把 Bootloader、App、默认参数合并为一个 hex 文件，一次烧录完成，避免漏烧。可以用 srec_cat 等工具合并。
  2. 写入唯一数据：序列号、MAC 地址、密钥、校准系数等每台设备不同的数据，由生产工具在烧录后写入指定 Flash 地址，或通过串口命令写入。很多 MCU 有出厂唯一 ID（UID），可作为设备标识的来源。
  3. 配置选项字节：开启读保护、配置 BOR 阈值、看门狗硬件启动等，放在烧录流程的最后一步。
  4. 校验与测试：烧录后读回校验，再运行产线自检程序（检测各接口、传感器、按键、LED），结果上传到生产系统。
  5. 记录与追溯：记录每台设备的序列号、固件版本、烧录时间、测试结果，返修时能查到这台设备的完整信息。
/* STM32 96 位唯一 ID（地址因系列而异，以手册为准），可派生设备序列号或 MAC */
#define UID_BASE_ADDR  0x1FFF7A10UL           /* STM32F4 */
void get_uid(uint32_t out[3])
{
    const volatile uint32_t *uid = (const volatile uint32_t *)UID_BASE_ADDR;
    out[0] = uid[0];
    out[1] = uid[1];
    out[2] = uid[2];
}

6. 工作场景：设计一个产线测试固件

产线测试有两种常见做法：一是单独烧录测试固件，测试完成后再烧录正式固件；二是在正式固件中内置“工厂模式”，通过特定条件进入。后者节省一次烧录，更常用：

  • 进入条件：上电时检测某个测试点被拉低，或串口收到特定命令。条件要足够“不会被用户误触发”。
  • 测试项目：读取各传感器是否在合理范围、通信接口回环测试、按键和指示灯配合治具检测、Flash 读写测试、电压和电流采样校准。
  • 输出格式：机器可解析的结果（如每项一行 ITEM=VOLT,RESULT=PASS,VALUE=3302），便于上位机或测试工装自动判定。
  • 退出与锁定：测试完成、写入序列号和校准数据后，写入“已出厂”标志，正常上电不再进入工厂模式，防止用户误入。

7. 调试与量产烧录检查清单

  • 硬件是否预留了 SWDIO、SWCLK、NRST、GND、VCC，量产板是否保留了测试点。
  • 软件是否避免过早把 SWD 引脚复用为 GPIO，调试低功耗时是否开启了调试保持。
  • 是否掌握 Connect Under Reset 和 BOOT0 等“救砖”手段。
  • 是否使用 SWO、RTT、数据断点、DWT 计数器等工具辅助调试，而不仅仅是断点。
  • 烧录是否脚本化，量产固件是否合并为单一文件。
  • 序列号、校准数据等唯一数据的写入地址和格式是否明确，是否记录可追溯信息。
  • 读保护、BOR 等选项字节是否在流程最后配置，并在样品上验证过。
  • 产线测试是否覆盖关键接口，工厂模式是否有可靠的进入和退出机制。
