MCU ADC 采样与模拟前端

整理 MCU ADC 读数不准的常见原因与对策：关键参数、采样时间与源阻抗、参考电压与 VREFINT 校准、定时触发加 DMA 的多通道采样、软件滤波与过采样、硬件布局，以及电池电压与 NTC 温度采集实例。

1. ADC 为什么经常“读不准”

ADC 的配置代码往往只有十几行，但读数跳动、偏大偏小、换个通道就不对，是嵌入式项目里最常见的抱怨之一。原因通常不在 ADC 本身，而在它周围：信号源阻抗太大、采样时间太短、参考电压不稳、布线引入噪声、软件滤波方式不合适。

ADC 的结果最终是一个比例：读数 / 满量程 = 输入电压 / 参考电压。任何影响输入电压或参考电压的因素，都会直接反映到读数上。

3. 采样时间与信号源阻抗

MCU 的 SAR 型 ADC 内部有一个几 pF 的采样电容。采样阶段，外部信号通过源阻抗给这个电容充电；采样时间不够，电容还没充到输入电压就开始转换，读数就会偏低。多通道扫描时，采样电容上还残留着上一个通道的电压，表现为“通道之间互相串扰”。

常见场景与对策：

  • 电阻分压测电池电压：为了降低功耗，分压电阻常选到几百 kΩ，源阻抗很大。对策是在 ADC 引脚对地并联一个 100nF 左右的电容（作为采样时的“电荷水库”），并适当延长采样时间。代价是信号带宽变低，只适合慢变信号。
  • NTC 热敏电阻：阻值随温度变化，高温或低温时阻值可能很大，同样需要并联电容和足够的采样时间。
  • 快速变化的信号（电流采样）：不能靠大电容滤波，应使用运放缓冲，降低源阻抗。

手册通常会给出“采样时间与最大允许源阻抗”的对照表，选择采样时间时应查表，而不是凭感觉设置。

4. 参考电压与校准

  • Vref 就是基准：很多小封装 MCU 的 Vref 内部连接到 VDDA，即模拟电源。电源纹波、LDO 精度直接影响读数。精度要求高的场合应使用独立的基准源，或者对 VDDA 做实时测量补偿。
  • 内部参考电压通道 VREFINT：STM32 等芯片内部有一个精确的带隙基准（约 1.2V），出厂时在固定的 VDDA 下测量并把读数写入系统存储区作为校准值（STM32F4 的校准条件为 3.3V，L4、G0 等系列为 3.0V，以手册为准）。通过测量 VREFINT 可以反推出实际的 VDDA：
/* 校准值地址与校准电压见手册：此处以 VREFINT_CAL_ADDR、VREFINT_CAL_MV 表示 */
#define VREFINT_CAL     (*(const uint16_t *)VREFINT_CAL_ADDR)
#define VREFINT_CAL_MV  3300U          /* STM32F4 为 3300，L4 / G0 等为 3000 */

uint32_t vdda_mv(uint16_t vrefint_raw)
{
    return VREFINT_CAL_MV * VREFINT_CAL / vrefint_raw;
}

uint32_t channel_mv(uint16_t raw, uint16_t vrefint_raw)
{
    /* 用实际 VDDA 换算，消除电源电压波动带来的误差 */
    return (uint32_t)raw * vdda_mv(vrefint_raw) / 4095U;
}
  • 自校准：STM32F1、L4、G0 等系列的 ADC 带硬件自校准功能，上电后、开启 ADC 之前执行一次，可以消除偏移误差。不同系列的校准时机要求不同（有的要求 ADC 关闭时校准），按手册顺序操作。
  • 两点标定：对整机精度有要求的产品，在生产时用标准源输入两个已知电压，计算增益和偏移系数并写入 Flash，运行时按系数修正。

5. 多通道扫描、DMA 与定时触发

多通道采样的推荐组合是：定时器触发 + 扫描模式 + DMA 循环搬运。

  • 定时器按固定频率触发转换，采样间隔由硬件保证，不受中断延迟影响。
  • 扫描模式下 ADC 依次转换规则组中的各个通道。
  • DMA 把每个结果写入数组对应位置，循环模式下自动从头覆盖，CPU 只在需要时读取数组。
#define ADC_CH_COUNT 4U
static volatile uint16_t adc_raw[ADC_CH_COUNT];   /* DMA 目标：0=电池 1=NTC 2=电流 3=VREFINT */

/* 读取时注意：DMA 可能正在更新数组。对一致性要求高时，可用半传输 / 传输完成中断做双缓冲 */
uint16_t adc_get(uint8_t ch)
{
    return adc_raw[ch];
}

要点：DMA 目标数组声明为 volatile；数组元素的顺序与规则组中通道的顺序严格对应；在带 Cache 的芯片上，DMA 目标缓冲区还要处理 Cache 一致性。

6. 软件滤波与过采样

方法原理适用
算术平均N 次求和除以 N去除随机噪声，最常用
去极值平均排序后去掉最大最小再平均偶发尖峰干扰
中值滤波取 N 次中间值脉冲干扰明显的场合
一阶低通（指数平均）y += (x - y) / k连续数据流，占用内存少
过采样采样 4^n 次求和，右移 n 位在噪声足够的前提下提升 n 位有效分辨率

过采样的原理是：在存在足够随机噪声的情况下，采样 4 次求和后右移 1 位，可以得到多 1 位的有效分辨率。12 位 ADC 采样 16 次求和右移 2 位得到 14 位结果。部分 STM32（L4、G0、G4 等）带硬件过采样单元，可直接在硬件中完成累加和移位。整数滤波的实现细节见 整数运算、溢出与定点数。

7. 硬件布局与模拟电源

软件能做的有限，很多 ADC 问题必须在硬件上解决：

  • 模拟电源去耦：VDDA / VREF+ 引脚就近放置 100nF + 1uF 电容；有条件时 VDDA 通过磁珠或独立 LDO 与数字电源隔离。
  • 抗混叠 RC：ADC 输入端加 RC 低通滤波，截止频率低于采样频率的一半，滤除高频干扰。
  • 走线：模拟信号远离时钟线、PWM 线和开关电源；模拟地与数字地在一点连接。
  • 采样时刻避开干扰：开关电源、电机 PWM 动作瞬间噪声最大，用定时器把采样点同步到安静时段。

8. 工作场景：电池电压与 NTC 温度采集

需求：电池电压 3.0~4.2V，经 1:2 分压（两个 100kΩ 电阻）接入 ADC；NTC 10kΩ（B=3950）与 10kΩ 固定电阻分压测温。

  1. 两个 ADC 引脚各并联 100nF 电容，采样时间选择手册中对应 50kΩ 源阻抗的档位（分压电阻并联后为 50kΩ）。
  2. 规则组配置为：电池、NTC、VREFINT 三个通道，定时器每 10ms 触发一次，DMA 循环搬运。
  3. 每 100ms 取最近 10 组数据做去极值平均。
  4. 电池电压按 VREFINT 实测的 VDDA 换算，消除 LDO 精度和温度漂移的影响。
  5. NTC 读数换算为电阻值后查表插值得到温度，表格存放在 Flash 中，以 0.1℃ 为单位的整数输出。
/* NTC 与上拉电阻 R_FIX 分压，NTC 接地：Rntc = R_FIX × raw / (4095 - raw) */
static inline uint32_t ntc_ohm(uint16_t raw)
{
    if (raw >= 4095U) return UINT32_MAX;              /* 开路 */
    return (uint32_t)((uint64_t)10000U * raw / (4095U - raw));
}

还要考虑传感器故障：NTC 开路时读数接近满量程，短路时接近 0，两种情况都应识别为“传感器故障”并上报，而不是换算出一个离谱的温度参与控制。

9. ADC 检查清单

  • 采样时间是否根据信号源阻抗查表选择，高阻信号源是否并联了电容或增加了缓冲。
  • 参考电压来源是否明确，是否需要用 VREFINT 补偿 VDDA 的波动。
  • 是否按手册顺序执行了 ADC 自校准，产品是否需要两点标定。
  • 多通道采样是否使用定时器触发 + DMA，结果数组顺序是否与通道顺序一致。
  • 滤波方式是否与干扰类型匹配，整数运算是否会溢出。
  • 模拟电源去耦、抗混叠 RC、走线隔离是否到位，采样时刻是否避开了 PWM 等强干扰。
  • 传感器开路、短路等异常读数是否被识别并处理。
