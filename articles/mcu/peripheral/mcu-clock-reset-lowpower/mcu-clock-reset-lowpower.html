MCU 时钟、复位与低功耗

整理 MCU 时钟树配置、复位源与复位原因记录、看门狗的正确用法和低功耗模式，并给出睡眠电流超标的排查步骤与电池寿命估算方法。

1. 时钟、复位与功耗：系统的地基

时钟决定了 CPU 和外设跑多快、计时准不准；复位决定了系统在异常时能否回到已知状态；功耗决定了电池能用多久。这三者在项目初期配置一次后很少再动，但一旦出问题，影响的是整个系统：串口波特率不准、设备偶尔重启、电池一周就耗尽。

2. 时钟树与时钟源

时钟源特点用途
内部高速 RC（HSI）无需外部器件，启动快；精度约 ±1%，随温度漂移启动阶段、对精度要求不高的应用
外部高速晶振（HSE）精度高（几十 ppm），需要晶振和负载电容UART 长期通信、USB、CAN、精确计时
PLL把 HSI 或 HSE 倍频到高主频系统主时钟
内部低速 RC（LSI）约 32kHz，精度差（可达 ±10% 以上）独立看门狗、低精度唤醒
外部低速晶振（LSE）32.768kHz，精度高，功耗极低RTC 实时时钟

需要高精度时钟的外设：USB 要求时钟精度约 ±0.25%（全速设备），用 HSI 一般无法满足（部分芯片通过 USB SOF 信号校准内部 RC 来实现免晶振 USB）；CAN 总线对位时间精度要求也较高，通常使用外部晶振。

配置时钟的正确顺序（以切换到 PLL 高主频为例）：

  1. 启动 HSE，等待就绪（带超时）。
  2. 配置并启动 PLL，等待锁定。
  3. 先设置 Flash 等待周期，再切换系统时钟——反过来会因为 Flash 读取跟不上而跑飞。
  4. 设置 AHB / APB 分频，确保各总线不超过最大频率。
  5. 切换系统时钟源到 PLL，并确认切换成功。

晶振不起振是新板子常见问题：负载电容不匹配、走线过长、晶振本身规格不符。代码里等待 HSE 就绪的循环必须有超时，超时后回退到 HSI 并记录故障，而不是卡死。STM32 的时钟安全系统（CSS）还能在 HSE 运行中失效时自动切换到 HSI 并产生 NMI 中断。

3. 复位源与复位原因

复位源触发条件排查方向
上电复位（POR）电源从 0 上升正常启动
欠压复位（BOR）电源电压低于阈值电池耗尽、负载突变导致电压跌落、电源设计余量不足
外部引脚复位（NRST）复位引脚被拉低复位按键、外部看门狗、调试器
独立看门狗（IWDG）未按时喂狗程序卡死、某个任务阻塞、喂狗周期设计不当
窗口看门狗（WWDG）喂狗过早或过晚程序执行时序异常
软件复位调用 NVIC_SystemReset()正常的复位操作，如升级完成、断言失败处理
低功耗复位进入某些低功耗模式时的非法操作低功耗配置错误

复位原因一定要记录。上电后读取复位标志寄存器（STM32 为 RCC->CSR），判断复位类型后清除标志，并写入日志或上报。“设备偶尔重启”是现场最常见的问题之一，没有复位原因就只能猜。

const char *reset_reason(void)
{
    uint32_t csr = RCC->CSR;
    RCC->CSR |= RCC_CSR_RMVF;                    /* 清除标志，否则下次复位时会叠加 */
    if (csr & RCC_CSR_LPWRRSTF) return "low-power";
    if (csr & RCC_CSR_WWDGRSTF) return "wwdg";
    if (csr & RCC_CSR_IWDGRSTF) return "iwdg";
    if (csr & RCC_CSR_SFTRSTF)  return "software";
    if (csr & RCC_CSR_BORRSTF)  return "brown-out";
    if (csr & RCC_CSR_PINRSTF)  return "pin";    /* 很多复位都会伴随 PIN 标志，所以放在后面判断 */
    return "unknown";
}

各系列的标志位名称和组合关系略有差异（例如上电复位时可能同时置位 BOR 和 PIN 标志），需要对照手册确定判断顺序。

BOR 阈值：开启欠压复位并选择合适的阈值，可以避免电压缓慢下降时 MCU 在“半工作”状态下运行，写坏 Flash 或输出错误控制信号。

4. 看门狗的正确用法

对比独立看门狗 IWDG窗口看门狗 WWDG
时钟独立的 LSI，主时钟失效也能工作APB 时钟
喂狗要求超时前喂即可必须在窗口时间内喂，过早也会复位
能否关闭启动后通常无法关闭可以
适用防止程序卡死，几乎所有产品都应开启检测时序异常，如程序跑飞后以错误的频率循环

几个工程要点：

  • 不要在定时器中断里无条件喂狗，应由监控任务确认所有关键任务都正常后才喂狗（实现见 调试与工程排错）。
  • 长时间操作（擦除 Flash、等待模组启动）前后要考虑喂狗，或者把操作拆分。
  • 调试时程序停在断点上会导致看门狗复位，多数芯片可以配置“调试暂停时冻结看门狗”（如 STM32 的 DBGMCU 冻结位）。
  • 低功耗模式下 IWDG 仍在运行，睡眠时间不能超过看门狗超时，需要定期唤醒喂狗，或者选用支持低功耗下冻结看门狗的芯片和选项字节配置。

5. 低功耗模式

以 STM32 为例，常见的低功耗模式按功耗从高到低排列：

模式CPU时钟RAM唤醒源典型电流唤醒后
Sleep停止外设时钟保持保持任意中断mA 级从中断处继续
Stop停止高速时钟关闭保持外部中断、RTC、部分外设几 uA ~ 几十 uA继续执行，但需要重新配置时钟
Standby停止几乎全部关闭丢失（备份域除外）唤醒引脚、RTC、复位1uA 以下 ~ 几 uA相当于复位重启

要点：

  • Stop 模式唤醒后时钟回到内部 RC（STM32F4 为 HSI，L4 等系列可选 MSI 或 HSI），必须重新配置 PLL，否则后续的波特率、定时器频率都不对。
  • Standby 唤醒等于复位，需要保存的状态要写入备份寄存器或 Flash，程序通过复位标志判断是“唤醒”还是“上电”。
  • 进入睡眠前关闭不用的外设：ADC、比较器、DAC、内部参考电压在 Stop 模式下可能仍在耗电。
  • SysTick 会频繁唤醒 CPU：用 RTOS 时应启用 tickless 模式，空闲时停止节拍中断，由低功耗定时器唤醒。

6. 工作场景：睡眠电流比手册大 100 倍

手册标称 Stop 模式 2uA，实测却有 200uA，这是低功耗产品开发中几乎必然遇到的情况。按下面的顺序排查：

  1. 先测“纯净”的芯片电流：写一个最小程序，初始化后立即进入 Stop 模式，确认能否达到手册值。达不到说明是硬件问题（电源芯片静态电流、外围器件漏电、测量方法）。
  2. 逐个检查 GPIO：悬空的数字输入、与外部电路存在压差的输出、开着上拉的引脚接在了低电平上，都会产生电流。睡眠前把未使用的引脚设为模拟模式，用到的引脚设到“不消耗电流”的电平。
  3. 检查外设：ADC、内部参考、比较器、调试接口（调试器连接时芯片无法真正进入低功耗）。测量时要断开调试器。
  4. 检查外围器件：LDO 的静态电流（普通 LDO 可达几十 uA，低功耗产品需选择 1uA 级的型号）、传感器是否进入了休眠、上拉电阻上的电流、指示 LED。
  5. 测量工具：普通万用表在 uA 档的内阻会影响电路，且无法看到电流的动态变化。推荐使用电流分析仪（如 Nordic PPK2、Joulescope），可以看到每次唤醒的电流波形和平均功耗。

电池寿命估算要按平均电流计算：例如每 10 秒唤醒一次、每次 5mA 工作 20ms，其余时间 3uA，平均电流约为 5mA × 0.02/10 + 3uA ≈ 13uA，220mAh 的纽扣电池理论可用约 1.9 年（实际还要考虑电池自放电和低温容量衰减，通常打七折）。

7. 时钟、复位与低功耗检查清单

  • 时钟源选择是否满足外设精度要求（USB、CAN、长期 UART 通信）。
  • 切换高主频时是否先设置 Flash 等待周期，等待 HSE / PLL 就绪是否有超时和回退。
  • 上电是否读取并记录复位原因，并清除复位标志。
  • 是否开启 BOR，阈值是否合适。
  • 看门狗是否由监控任务确认所有任务正常后才喂，调试时是否冻结看门狗。
  • 低功耗唤醒后是否重新配置时钟，Standby 模式需要保存的状态是否已妥善保存。
  • 睡眠前是否检查了每个 GPIO 的状态、关闭了不用的外设，测量时是否断开了调试器。
  • 电池寿命是否按平均电流估算，并考虑了自放电和温度影响。
