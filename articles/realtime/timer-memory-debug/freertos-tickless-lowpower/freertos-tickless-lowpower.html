FreeRTOS Tickless 与低功耗

说明 Tickless Idle 的原理，内置 SysTick 实现的限制，以及用 LPTIM 自定义实现进入 Stop 模式的方法和常见功耗问题。

1. 为什么需要 Tickless

FreeRTOS 依靠周期性的 Tick 中断（通常 1ms）推进时间。即使所有任务都在阻塞等待，CPU 也会每毫秒被唤醒一次处理 Tick，这对电池供电设备是很大的浪费：

普通模式：  |T|T|T|T|T|T|T|T|T|T|   每 1ms 唤醒一次，CPU 无法长时间休眠
Tickless：  |T|.......休眠.......|T|  预计空闲 N 个 Tick，就停掉 Tick 休眠 N 个 Tick

Tickless Idle 的思路是：当调度器发现下一个任务要在 N 个 Tick 之后才就绪时，停止周期 Tick，设置一个定时器在 N 个 Tick 后唤醒，进入低功耗模式；醒来后把错过的 Tick 数补回内核时间。MCU 本身的低功耗模式与时钟配置见 时钟、复位与低功耗。

2. 最简单的开始：空闲钩子中执行 WFI

不启用 Tickless 时，也可以在空闲任务钩子中让 CPU 进入 Sleep 模式，下一次中断（包括 Tick）到来时自动唤醒：

/* FreeRTOSConfig.h: #define configUSE_IDLE_HOOK 1 */
void vApplicationIdleHook(void)
{
    __DSB();
    __WFI();        /* Sleep 模式：内核时钟停止，外设和 SysTick 继续运行 */
}

这种方式简单安全，但每个 Tick 都会唤醒，节能效果有限。空闲钩子中不能调用任何可能阻塞的 API。

3. 使用内置 Tickless 实现

Cortex-M 等常见移植已经提供了基于 SysTick 的默认 Tickless 实现，只需配置：

/* FreeRTOSConfig.h */
#define configUSE_TICKLESS_IDLE                 1   /* 1：使用移植层默认实现；2：自己实现 */
#define configEXPECTED_IDLE_TIME_BEFORE_SLEEP   2   /* 预计空闲至少 2 个 Tick 才休眠 */

/* 进入休眠前后的钩子，可用于关闭 / 恢复外设时钟 */
#define configPRE_SLEEP_PROCESSING(x)   app_pre_sleep(&(x))
#define configPOST_SLEEP_PROCESSING(x)  app_post_sleep(&(x))
void app_pre_sleep(TickType_t *expected_ticks)
{
    led_off();
    /* 如果有不能被打断的传输正在进行，可以把 *expected_ticks 置 0，
       移植层将跳过本次 WFI */
}

void app_post_sleep(TickType_t *expected_ticks)
{
    (void)expected_ticks;
}

默认实现的限制：它使用 SysTick 定时唤醒，而 SysTick 是 24 位计数器、以内核时钟计数。内核时钟 80MHz 时，最长一次休眠约 2^24 / 80MHz ≈ 0.21s，超过后会提前醒来再次休眠。更关键的是，SysTick 在 Stop 等深度低功耗模式下停止工作，所以默认实现只能配合 Sleep 模式使用。

4. 自定义实现：用低功耗定时器进入 Stop 模式

要进入 Stop 模式（电流从毫安级降到微安级），需要用在 Stop 模式下仍能运行的定时器（如 STM32 的 LPTIM 或 RTC 唤醒定时器）替代 SysTick，并设置 configUSE_TICKLESS_IDLE 2，自己实现 portSUPPRESS_TICKS_AND_SLEEP()：

/* FreeRTOSConfig.h */
#define configUSE_TICKLESS_IDLE   2
extern void app_suppress_ticks_and_sleep(TickType_t expected_idle);
#define portSUPPRESS_TICKS_AND_SLEEP(x)  app_suppress_ticks_and_sleep(x)
/* 示意：LPTIM 以 LSE 32.768kHz 计数，用于计算休眠时长 */
void app_suppress_ticks_and_sleep(TickType_t expected_idle)
{
    if (expected_idle > MAX_LPTIM_TICKS) expected_idle = MAX_LPTIM_TICKS;

    __disable_irq();                                     /* 屏蔽中断，但 WFI 仍可被挂起的中断唤醒 */
    if (eTaskConfirmSleepModeStatus() == eAbortSleep) {  /* 关中断前有任务变为就绪 */
        __enable_irq();
        return;
    }

    SysTick->CTRL &= ~SysTick_CTRL_ENABLE_Msk;           /* 停止 SysTick */
    lptim_start_oneshot(ticks_to_lptim(expected_idle));  /* 设置唤醒时间 */

    enter_stop_mode();                                   /* WFI，进入 Stop */
    /* --- 被 LPTIM 或其他中断唤醒 --- */
    restore_system_clock();                              /* Stop 唤醒后时钟回到 HSI/MSI，需要重新配置 PLL */

    uint32_t slept = lptim_to_ticks(lptim_elapsed());    /* 实际休眠了多少个 Tick */
    lptim_stop();
    vTaskStepTick(slept);                                /* 补回内核时间（不能超过 expected_idle） */

    SysTick->VAL = 0;
    SysTick->CTRL |= SysTick_CTRL_ENABLE_Msk;            /* 恢复 SysTick */
    __enable_irq();                                      /* 唤醒中断在此之后得到处理 */
}

实现中要特别注意：

  • 提前唤醒：可能被按键、串口等其他中断提前唤醒，必须用实际经过的时间而不是预计时间来补偿 Tick。
  • 时钟恢复：多数 MCU 从 Stop 模式唤醒后使用内部 RC 振荡器，需要重新开启 PLL 并切换系统时钟，外设波特率等才正确。
  • 时间精度：LPTIM 计数与 Tick 之间的换算会产生舍入误差，长时间运行后系统时间会漂移；需要精确时间时以 RTC 为准。

5. 哪些东西会阻止休眠

启用 Tickless 后功耗仍然下不去，常见原因：

原因现象处理
有任务周期性短延时（如 vTaskDelay(1) 轮询）预计空闲时间始终小于阈值改为事件驱动阻塞等待
软件定时器周期很短定时器任务频繁就绪合并定时器、加大周期
外设时钟没有关闭Stop 模式电流偏大在休眠前关闭不用的外设时钟
GPIO 浮空电流偏大且不稳定未使用引脚配置为模拟输入
调试器连接低功耗模式下调试器保持时钟断开调试器测量，或关闭 DBGMCU 低功耗调试位
正在进行的 DMA / 通信进入 Stop 后传输中断在 pre-sleep 中检查并跳过休眠

可以在休眠入口和唤醒处翻转 GPIO，用示波器或功耗分析仪观察实际休眠时长和唤醒频率。

6. 工作场景：电池供电传感器节点

需求：STM32L4 + LoRa 模块，每 5 分钟采集一次温湿度并上报，按键可随时唤醒，目标平均电流低于 20uA。

  1. 任务结构：采集任务 vTaskDelayUntil 5 分钟；通信任务等待消息；按键通过 EXTI 中断通知业务任务。除此之外没有周期性任务。
  2. Tickless：configUSE_TICKLESS_IDLE 2，LPTIM1 使用 LSE 计数，空闲时进入 Stop 2 模式。
  3. 外设管理：采集前打开传感器电源和 I2C 时钟，采集完成立即关闭；LoRa 模块发送完成后进入睡眠。
  4. 唤醒处理：唤醒后恢复 PLL；串口只在需要时启用。
  5. 测量：用功耗分析仪记录一个完整周期的电流曲线，分别统计休眠电流、采集峰值和发送峰值，计算平均电流并估算电池寿命。
  6. 验证：长时间运行检查系统时间漂移、按键唤醒响应和看门狗（IWDG 在 Stop 模式下仍运行，需要定时唤醒喂狗或配置合适的超时）。

7. 低功耗检查清单

  • 是否启用了合适的休眠方式：空闲钩子 WFI、内置 Tickless（Sleep），或自定义 Tickless（Stop）。
  • 自定义实现是否使用在低功耗模式下仍运行的定时器，是否按实际休眠时间补偿 Tick。
  • 唤醒后是否正确恢复系统时钟和外设配置。
  • 任务和软件定时器是否消除了不必要的短周期唤醒。
  • 休眠前是否关闭了不用的外设时钟，未使用引脚是否配置为模拟输入。
  • 是否在断开调试器的情况下实测过休眠电流和平均电流。
  • 独立看门狗在低功耗模式下的行为是否考虑过。
  • 长时间运行后系统时间漂移是否在可接受范围内。
