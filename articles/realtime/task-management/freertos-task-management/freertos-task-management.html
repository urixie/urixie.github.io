FreeRTOS 任务管理与栈空间

FreeRTOS 的任务可以理解为嵌入式系统中的轻量线程。每个任务都有自己的任务函数.栈空间.优先级和任务控制块。任务设计是否合理，会直接影响系统实时性.稳定性和可维护性。

1.任务创建

常用 xTaskCreate() 创建动态任务，也可以用 xTaskCreateStatic() 创建静态任务。动态任务由 FreeRTOS 堆分配任务控制块和栈，静态任务由用户提供内存，更适合对内存确定性要求高的项目。 

static void led_task(void *arg)
{
    (void)arg;

    while (1) {
        led_toggle();
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}

xTaskCreate(led_task, "led", 1024, NULL, 1, NULL);

任务函数通常是一个不会返回的无限循环。如果任务确实要结束，应调用 vTaskDelete(NULL) 删除自己。

2.任务句柄

任务句柄用于操作指定任务，例如删除.挂起.恢复.通知等。创建任务时可以保存句柄。 

static TaskHandle_t s_uart_task_handle;

xTaskCreate(uart_task,
            "uart",
            2048,
            NULL,
            3,
            &s_uart_task_handle);

如果后续不需要主动控制任务，可以把最后一个参数传 NULL。如果需要从中断或其它任务通知该任务，建议保存句柄。

3.任务优先级设计

优先级应该按实时性和阻塞行为设计，而不是按“功能重要性”随意设置。高优先级任务应该尽快完成处理并进入阻塞态。

  • 硬实时响应任务：优先级较高，但必须短小。
  • 通信接收任务：通常高于普通业务任务。
  • 显示刷新任务：优先级不宜过高，避免影响采样和通信。
  • 日志.存储.统计任务：一般优先级较低。
高优先级任务如果写成无阻塞死循环，会饿死低优先级任务。这类问题表现为系统某些功能不运行，但并不一定死机。

4.任务延时：vTaskDelay 与 vTaskDelayUntil

vTaskDelay() 是相对延时，从当前调用时刻开始等待指定 Tick。vTaskDelayUntil() 是周期性延时，适合固定周期任务。 

void sample_task(void *arg)
{
    TickType_t last_wake = xTaskGetTickCount();

    while (1) {
        adc_sample_once();
        vTaskDelayUntil(&last_wake, pdMS_TO_TICKS(10));
    }
}

周期采样.周期控制.定时通信更适合用 vTaskDelayUntil()，它比简单 vTaskDelay() 更容易维持稳定周期。

5.任务栈空间

每个 FreeRTOS 任务都有独立栈。任务栈用于保存局部变量.函数调用上下文.中断嵌套时的部分上下文等。栈太小会导致栈溢出，栈太大又会浪费 RAM。

6.栈水位检测

FreeRTOS 提供栈水位检测接口，可以查看任务历史运行过程中剩余栈空间的最小值。调试阶段建议重点关注通信.显示.文件系统.协议解析等任务。 

UBaseType_t watermark = uxTaskGetStackHighWaterMark(NULL);
printf("stack watermark = %u\n", (unsigned)watermark);

如果水位值很小，说明任务栈接近耗尽，需要增大栈或减少局部变量占用。尤其不要在任务函数里定义几 KB 的局部数组。

7.任务设计检查清单

  • 任务职责是否单一。
  • 任务是否有明确阻塞点。
  • 优先级是否按实时性设计。
  • 任务栈是否经过水位检测。
  • 是否避免局部大数组。
  • 任务删除前是否释放相关资源。
  • 周期任务是否使用 vTaskDelayUntil()。
