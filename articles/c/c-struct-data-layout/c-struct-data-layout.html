C语言结构体与数据组织整理

本文整理 C 语言中结构体、联合体、枚举、位域和数据布局的工程用法。重点面向参数表、通信协议、寄存器映射、Flash 存储和上位机 / 下位机数据一致性设计。

结构体的价值不是把变量简单打包，而是把一组相关数据变成有边界、有含义、可传递、可维护的工程对象。

一、为什么嵌入式项目离不开结构体

嵌入式工程中常常需要管理成组数据，例如设备参数、通信帧、传感器采样结果、错误状态、升级包头部、Flash 存储记录等。结构体可以让这些字段具有清晰的组织关系。

  • 让参数配置从零散变量变成表格化数据。
  • 让协议帧解析更容易维护。
  • 让模块接口更清晰，减少函数参数数量。
  • 让 Flash 存储、CRC 校验和版本管理更有结构。

二、struct 的基本用法

struct 用来定义一组相关字段。建议使用 typedef 定义清晰的类型名，字段命名要表达单位、范围和含义。 

typedef struct {
    uint16_t voltage_mv;
    uint16_t current_ma;
    int16_t temperature_centi_deg;
    uint8_t status;
} device_sample_t;

命名时建议把单位写进字段名，例如 voltage_mv 表示毫伏，temperature_centi_deg 表示百分之一摄氏度，避免多人维护时误用单位。

三、结构体数组与参数表

当参数数量较多时，不建议为每个参数单独写一套变量和处理函数。可以使用结构体数组描述参数表，把名称、地址、默认值、上下限和属性集中管理。 

typedef struct {
    uint8_t address;
    const char *name;
    uint16_t default_value;
    uint16_t min_value;
    uint16_t max_value;
    uint8_t flags;
} param_item_t;

static const param_item_t g_param_table[] = {
    {0, "输出电压", 2200, 0, 3000, 0},
    {1, "保护阈值", 2500, 0, 4095, 0},
};

参数表的优势是后续可以统一生成界面、统一校验范围、统一存储到 Flash，也便于与上位机配置文件保持一致。

四、union 的作用与风险

union 的所有成员共享同一段内存。它适合用于同一段数据的多种解释方式，例如把 32 位值按字节访问。但它也容易引入大小端、对齐和可读性问题。 

typedef union {
    uint32_t value;
    uint8_t bytes[4];
} u32_bytes_t;

如果数据需要跨平台或跨编译器传输，不建议依赖 union 的内存布局作为协议格式。更稳妥的方式是手动按字节打包和解包。

五、enum 枚举与状态机

枚举可以让状态值更可读。状态机、错误码、设备模式和事件类型都适合用枚举表达。 

typedef enum {
    APP_STATE_IDLE = 0,
    APP_STATE_INIT,
    APP_STATE_RUNNING,
    APP_STATE_ERROR,
} app_state_t;

static app_state_t s_state = APP_STATE_IDLE;

枚举值如果需要写入 Flash 或参与通信协议，建议显式指定数值，避免后续插入新枚举项导致协议兼容性问题。

六、位域与寄存器映射

位域可以把一个整数中的多个 bit 字段写成结构体形式，但其布局与编译器、字节序和 ABI 有关。对于寄存器配置或通信协议，位域要谨慎使用。 

typedef struct {
    uint8_t enable : 1;
    uint8_t mode   : 2;
    uint8_t fault  : 1;
    uint8_t unused : 4;
} status_bits_t;

如果要求跨平台稳定，优先使用掩码和位移操作。位域更适合内部状态描述，不适合直接作为外部协议或存储格式。

七、结构体对齐与 sizeof

编译器可能为了提升访问效率，在结构体字段之间插入填充字节。因此 sizeof(struct) 不一定等于所有字段大小之和。 

typedef struct {
    uint8_t a;
    uint32_t b;
    uint16_t c;
} example_t;

// sizeof(example_t) 可能大于 1 + 4 + 2

如果结构体要写入 Flash 或与上位机二进制文件对应，必须明确结构体版本、字段顺序、对齐策略和 CRC 范围。必要时不要直接写结构体，而是手动序列化。

八、协议帧和参数表设计示例

一个相对清晰的协议帧通常包含帧头、命令、长度、数据和校验。不要把裸结构体直接发送出去，建议通过函数进行打包。 

typedef struct {
    uint8_t header0;
    uint8_t header1;
    uint8_t cmd;
    uint16_t length;
    const uint8_t *payload;
    uint16_t crc;
} protocol_frame_t;

对于 72 个参数这类配置系统，可以用结构体数组描述元信息，用单独的值数组保存当前值，用序列化函数生成加密或校验后的 bin 文件。

九、结构体设计检查清单

  • 字段名是否带有单位和含义。
  • 是否显式指定了协议或存储字段的类型宽度。
  • 枚举值是否需要固定数值。
  • 结构体是否会被直接写入 Flash 或发送到上位机。
  • 是否考虑了结构体对齐和版本兼容。
  • 是否需要添加 magic、version、length、crc 等保护字段。
  • 是否把内部内存布局误当成外部协议格式。
