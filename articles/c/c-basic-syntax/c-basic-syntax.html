C语言基础语法整理

本文从嵌入式工程实践角度整理 C 语言基础语法。重点不是重复教材概念，而是把变量.类型.表达式.流程控制.函数和文件组织这些基础内容，放到单片机.驱动.通信协议和参数配置的场景中理解。

写嵌入式 C 时，基础语法的目标不是“能跑”，而是让数据宽度明确.执行路径清楚.接口边界稳定.代码后续可维护。

1.C 语言在嵌入式中的作用

嵌入式项目中，C 语言通常直接面对寄存器.外设.Flash.RAM.通信数据和中断。相比应用层开发，嵌入式 C 更关注数据宽度.内存位置.执行时序和硬件副作用。

  • 驱动层：读写寄存器.配置 GPIO.Timer.ADC.SPI.IIC.UART 等外设。
  • 协议层：组织帧头.命令字.长度.校验和数据区。
  • 业务层：实现参数管理.状态机.错误处理和设备控制逻辑。
  • 存储层：管理 Flash.EEPROM.NVS.文件系统或自定义 bin 配置。

2.变量.常量与基本数据类型

嵌入式项目中不建议长期依赖 int.long 这类宽度可能随平台变化的类型。对于协议.寄存器.Flash 存储和跨平台数据，优先使用 stdint.h 提供的定长类型。 

#include <stdint.h>
#include <stdbool.h>

uint8_t  flag;        // 8bit 标志或字节数据
uint16_t adc_value;   // 16bit ADC 或寄存器值
uint32_t tick_ms;     // 32bit 系统计数
bool     enabled;     // 布尔状态

如果变量表示硬件寄存器值.协议字段.文件格式字段，类型宽度必须固定。否则上位机.下位机.不同编译器之间可能出现解析不一致。

3.整型.浮点型与 char 的常见坑

C 语言中的整数运算可能发生溢出，且有符号和无符号混合比较时容易出现意外结果。嵌入式协议解析中，原始字节建议统一使用 uint8_t，不要直接使用 char 表示二进制数据。 

uint8_t rx = 0xFF;
uint16_t value = ((uint16_t)rx << 8) | 0x34;

// 不推荐：char 是否有符号与编译器实现有关
char raw = (char)0xFF;

浮点数适合物理量换算和界面显示，但不适合作为通信协议中的精确判等依据。需要跨设备传输时，常见做法是使用定点数，例如把 12.34V 放大 100 倍后存为整数 1234。

4.运算符与表达式

位运算是嵌入式 C 的核心能力。寄存器配置.状态标志.协议字段打包和权限标记都经常依赖按位与.按位或.按位取反.左移和右移。 

#define BIT(n)             (1U << (n))
#define REG_ENABLE_BIT     BIT(3)
#define REG_MODE_MASK      (0x03U << 4)

reg |= REG_ENABLE_BIT;             // 置位
reg &= ~REG_ENABLE_BIT;            // 清位
reg = (reg & ~REG_MODE_MASK) | (2U << 4);

对表达式加括号可以减少误读，尤其是宏定义.位移.比较和逻辑组合表达式。工程代码优先保证清晰，而不是追求一行写完。

5.流程控制的工程写法

if.switch.for.while 都很基础，但在工程中应当保持入口条件明确.退出条件明确.错误路径明确。循环中如果等待硬件状态，必须考虑超时退出。 

uint32_t timeout = 100000U;
while ((REG_STATUS & BUSY_FLAG) != 0U) {
    if (--timeout == 0U) {
        return ERR_TIMEOUT;
    }
}

状态较多时优先使用 switch 描述状态机，不要让多层 if else 把流程写得难以维护。

6.函数.参数传递与返回值

函数是工程代码的基本组织单元。嵌入式函数应尽量做到职责单1.输入输出清楚.错误码明确。不要让函数既初始化硬件.又处理协议.又刷新界面。 

typedef enum {
    APP_OK = 0,
    APP_ERR_PARAM,
    APP_ERR_TIMEOUT,
    APP_ERR_CRC,
} app_err_t;

app_err_t adc_read_channel(uint8_t channel, uint16_t *out_value)
{
    if (out_value == NULL) {
        return APP_ERR_PARAM;
    }

    // 读取 ADC，省略硬件细节
    *out_value = 0;
    return APP_OK;
}

指针参数用于输出结果时，函数开头必须判空。返回值建议表达函数是否执行成功，具体数据通过输出参数返回。

7.头文件与源文件组织

头文件用于声明对外接口，源文件用于实现内部逻辑。头文件不应该暴露过多内部变量和内部函数，否则模块边界会越来越混乱。 

// app_adc.h
#ifndef APP_ADC_H
#define APP_ADC_H

#include <stdint.h>
#include "app_error.h"

app_err_t app_adc_init(void);
app_err_t app_adc_read(uint8_t channel, uint16_t *out_value);

#endif

一个模块通常包含 .h 和 .c 两部分。外部只包含头文件，不直接依赖源文件内部的静态变量和静态函数。

8.基础语法检查清单

  • 协议.寄存器.Flash 数据是否使用了固定宽度类型。
  • 有符号和无符号变量是否混合比较。
  • 移位前是否确认了变量宽度，必要时是否强制类型转换。
  • 等待硬件状态的循环是否有超时退出。
  • 函数参数是否做了合法性检查。
  • 头文件是否只暴露必要接口。
  • 复杂表达式是否加括号提升可读性。
