FPGA FIFO 与 RAM

整理 FPGA 存储资源的选择与使用：寄存器、LUTRAM 与 BRAM 的区别、BRAM 推断写法、读延迟对齐、同步 FIFO 与 FWFT 模式、valid/ready 握手、FIFO 深度计算，以及乒乓缓存和图像行缓存。

1. FPGA 中的存储资源

FPGA 里能存数据的资源有三类，选择哪种直接影响资源占用和时序：

资源容量读延迟特点适用
寄存器（FF）每个 1 位0（组合读）/ 1 拍数量多，但用来存大数组极其浪费小型状态、流水线、少量查找表
分布式 RAM（LUTRAM）用 LUT 实现，几十到几百位一块异步读（组合）或 1 拍灵活、可异步读，占用逻辑资源小于几百字节的小型 RAM、小 FIFO
块 RAM（BRAM）7 系列为 36Kb / 块（可拆成两个 18Kb）同步读，1 拍（启用输出寄存器为 2 拍）专用硬核，容量大、不占逻辑数据缓存、大 FIFO、图像行缓存

存储需求超过片上资源时，就需要外部 SDRAM / DDR，那是另一个层次的设计。

2. 让综合工具推断出 BRAM

BRAM 既可以通过 IP 核生成，也可以用符合规范的 HDL 写法让综合工具自动推断。推断的好处是代码可移植，换厂商不用重新生成 IP：

// 简单双口 RAM：A 口写、B 口读，同一时钟
module sdp_ram #(
    parameter DW = 16,
    parameter AW = 10           // 1024 深度
) (
    input  wire          clk,
    input  wire          we,
    input  wire [AW-1:0] waddr,
    input  wire [DW-1:0] wdata,
    input  wire [AW-1:0] raddr,
    output reg  [DW-1:0] rdata
);
    reg [DW-1:0] mem [0:(1<<AW)-1];

    always @(posedge clk) begin
        if (we) mem[waddr] <= wdata;
        rdata <= mem[raddr];          // 同步读：地址在本拍给出，数据下一拍有效
    end
endmodule

写法要点：

  • 读必须是同步的（读地址或读数据寄存在时钟沿上），写成 assign rdata = mem[raddr]; 这样的异步读，工具只能用分布式 RAM 或寄存器实现，深度一大就会耗尽逻辑资源。
  • 不要对存储数组整体复位：for 循环清零整个数组会让工具无法映射到 BRAM。需要初始值时用 $readmemh 在初始化时加载，或在 IP 中配置初始化文件（.coe / .mif）。
  • 读写同一地址的行为（Read-First、Write-First、No-Change）随写法和器件不同而不同，依赖这一行为的设计要查看综合报告确认，或者在逻辑上避免同时读写同一地址。
  • 综合后查看资源报告，确认 RAM 确实被映射为 BRAM，而不是成千上万个寄存器。

安路、Lattice 等厂商的推断规则与 Xilinx 相近，但支持的端口组合和初始化方式有差异；使用 IP 生成器配置 RAM 的流程见 EF2 单口 RAM 实验。

3. 读延迟：最容易错的地方

BRAM 是同步读：这一拍给出地址，下一拍才得到数据；开启输出寄存器（改善时序）后还要再晚一拍。读延迟没有对齐，是 FPGA 存储相关 bug 的第一大来源，典型表现是“读出的数据总是错一个位置”。

// 读地址与有效信号同步延迟，保证 rdata 与 rvalid、对应的地址标签对齐
always @(posedge clk) begin
    rd_en_d1   <= rd_en;           // RAM 读延迟 1 拍
    raddr_d1   <= raddr;
end
assign rvalid = rd_en_d1;          // 与 rdata 同一拍有效

在仿真中检查读延迟最直接：给 RAM 写入地址作为数据（mem[i] = i），然后连续读出，看数据与地址是否正好错开预期的拍数。

4. 同步 FIFO

FIFO 是 FPGA 中最常用的缓冲结构，用于两个处理速率不同的模块之间。读写在同一时钟域时使用同步 FIFO：

module sync_fifo #(
    parameter DW = 8,
    parameter AW = 4                 // 深度 16
) (
    input  wire          clk, rst,
    input  wire          wr_en,
    input  wire [DW-1:0] wdata,
    input  wire          rd_en,
    output wire [DW-1:0] rdata,
    output wire          full, empty
);
    reg [DW-1:0] mem [0:(1<<AW)-1];
    reg [AW:0]   wptr, rptr;         // 多一位，用于区分空和满

    assign empty = (wptr == rptr);
    assign full  = (wptr[AW] != rptr[AW]) && (wptr[AW-1:0] == rptr[AW-1:0]);
    assign rdata = mem[rptr[AW-1:0]];          // 首字直通（FWFT）：小深度用 LUTRAM 实现

    always @(posedge clk) begin
        if (rst) begin
            wptr <= 0; rptr <= 0;
        end else begin
            if (wr_en && !full) begin
                mem[wptr[AW-1:0]] <= wdata;
                wptr <= wptr + 1'b1;
            end
            if (rd_en && !empty) rptr <= rptr + 1'b1;
        end
    end
endmodule

工程中更常用厂商的 FIFO IP（Xilinx FIFO Generator、XPM_FIFO_SYNC），它们提供可配置的深度、位宽转换、almost_full / almost_empty、数据计数和 ECC。使用前要搞清楚 IP 的两种读模式：

  • 标准模式：rd_en 拉高后的下一拍数据才出现在输出端。
  • 首字直通（FWFT）模式：只要 FIFO 非空，第一个数据就已经出现在输出端，rd_en 相当于“我已经取走了，换下一个”。

模式选错，读出的数据会整体错位一个。跨时钟域使用的异步 FIFO 原理见 跨时钟域处理。

5. 流控：valid / ready 握手

模块之间传递数据流时，推荐统一使用 valid / ready 握手（AXI-Stream 的基本思想）：

  • 发送方拉高 valid 表示数据有效，接收方拉高 ready 表示可以接收。
  • 只有 valid && ready 同时为高的那个时钟沿，才算完成一次传输。
  • 发送方一旦拉高 valid，在传输完成前不能撤销，也不能改变数据。
  • valid 不能依赖于 ready（否则可能形成组合环路或死锁），ready 可以依赖于 valid。

FIFO 天然适配这种接口：写端 ready = !full，读端 valid = !empty。在 FIFO 前后都用这套握手，模块之间就能自动处理反压：下游处理不过来时，ready 拉低，上游自动等待，不会丢数据。

assign s_ready = !fifo_full;                    // 上游：FIFO 不满就能接收
assign fifo_wr = s_valid && s_ready;            // 握手成功时写入
assign m_valid = !fifo_empty;                   // 下游：FIFO 非空就有数据
assign fifo_rd = m_valid && m_ready;            // 下游取走时读出（FWFT 模式）

6. FIFO 深度怎么算

FIFO 太浅会溢出，太深浪费 BRAM。计算的核心是：在最坏情况的突发期间，写入比读出多出来的数据量。

深度 ≥ 突发长度 × (1 - 读速率 / 写速率)    （读速率 < 写速率时）

例：ADC 以 80MHz 每拍写入 1 个样本，突发采集 2048 个样本；读端在 50MHz 时钟下，每拍读出 1 个样本。

突发持续时间 = 2048 / 80MHz = 25.6us
期间读出数量 = 25.6us × 50MHz = 1280
需要缓存     = 2048 - 1280 = 768  → 选择深度 1024（取 2 的幂，并留余量）

还要考虑读端的“空闲时间”：如果读端每读 8 个数据就要停 2 个周期（例如通过总线发送时的协议开销），读速率就要乘以 8/10 再计算。读速率持续低于写速率时，任何深度的 FIFO 最终都会溢出，这时需要降低写入速率或提高读出能力，而不是加大 FIFO。

7. 工作场景：乒乓缓存与图像行缓存

乒乓缓存：两块 RAM 交替使用，一块写入新数据时，另一块被读出处理，写满后交换角色。适合“整块采集、整块处理”的场景，例如采集 1024 点后做 FFT。

reg bank;                                   // 当前写入的 bank
always @(posedge clk)
    if (wr_en && waddr == DEPTH - 1)
        bank <= ~bank;                      // 写满一块后切换

assign we_a = wr_en && (bank == 1'b0);
assign we_b = wr_en && (bank == 1'b1);
assign rdata = bank ? rdata_a : rdata_b;   // 读的是“不在写”的那一块

需要保证处理一块数据的时间小于写满一块的时间，否则读端还没处理完，写端就会覆盖它。

图像行缓存：3×3 卷积、Sobel 边缘检测等图像算法需要同时访问相邻三行的像素。用两块 BRAM 各缓存一行，配合当前行的像素流，就能在每个时钟周期得到一个 3×3 窗口，而不需要缓存整帧图像。这是 FPGA 做实时图像处理的基础结构。

8. FIFO 与 RAM 检查清单

  • 存储大小是否选择了合适的资源（寄存器 / LUTRAM / BRAM），综合后是否确认映射正确。
  • 推断 BRAM 的写法是否为同步读，是否避免了对整个存储数组复位。
  • 读延迟（1 拍或 2 拍）是否与 valid、地址标签等控制信号对齐，并在仿真中验证。
  • 使用 FIFO IP 时，是否清楚标准模式与 FWFT 模式的区别。
  • 模块之间是否统一使用 valid / ready 握手，传输是否只在两者同时有效时完成。
  • FIFO 深度是否按突发长度和读写速率计算，是否考虑了读端的空闲时间。
  • 满、空、溢出、读空等异常是否有标志输出，并在调试时可以观察到。
