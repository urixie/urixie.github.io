FPGA 实现 UART、SPI 与 I2C

整理用 Verilog 实现串行接口的方法：UART 发送与中点采样接收、SPI 主机模式与时钟边沿、I2C 三态开漏与时钟拉伸、接口模块的设计规范，以及 FPGA 与 MCU 之间通信通道的选择。

1. FPGA 实现串行接口和 MCU 有什么不同

在 MCU 上，UART、SPI、I2C 都是现成的硬件外设，配置几个寄存器就能用。在 FPGA 上，这些接口需要用 HDL 自己实现（或使用 IP），每一个时序细节都由设计者负责。好处是完全可控：可以同时实例化十几个串口、实现非标准的协议变种、精确控制每一个时钟沿；代价是每个细节都要考虑周全。

三种接口在 FPGA 中的实现都遵循相同的结构：一个分频或波特率计数器产生时序节拍 + 一个移位寄存器收发数据 + 一个状态机控制流程。FPGA 内部仍然使用一个统一的高速系统时钟，接口时钟通过计数器产生“节拍使能”，而不是生成新的时钟。

2. UART 发送：波特率节拍 + 移位

module uart_tx #(
    parameter CLK_HZ = 50_000_000,
    parameter BAUD   = 115200
) (
    input  wire       clk,
    input  wire       rst,
    input  wire [7:0] data,
    input  wire       start,      // 单周期脉冲，busy 为低时有效
    output reg        tx,
    output wire       busy
);
    localparam integer DIV = (CLK_HZ + BAUD / 2) / BAUD;   // 四舍五入，50MHz/115200 ≈ 434

    reg [15:0] cnt;
    reg [3:0]  bit_idx;
    reg [9:0]  shift;                 // {停止位, 数据, 起始位}
    reg        active;

    assign busy = active;

    always @(posedge clk) begin
        if (rst) begin
            tx <= 1'b1; active <= 1'b0; cnt <= 0; bit_idx <= 0;
        end else if (!active) begin
            tx <= 1'b1;
            if (start) begin
                shift   <= {1'b1, data, 1'b0};
                active  <= 1'b1;
                cnt     <= 0;
                bit_idx <= 0;
            end
        end else if (cnt == DIV - 1) begin
            cnt <= 0;
            tx  <= shift[0];
            shift <= {1'b1, shift[9:1]};
            if (bit_idx == 4'd9) active <= 1'b0;
            bit_idx <= bit_idx + 1'b1;
        end else begin
            cnt <= cnt + 1'b1;
        end
    end
endmodule

这个实现中，发送的第一位（起始位）要等一个完整的波特率周期后才输出，属于可以接受的固定延迟。波特率误差的计算方法与 MCU 相同：50MHz / 434 = 115207bps，误差约 0.006%，完全可以忽略。系统时钟较低、波特率较高时要核算误差，见 UART、SPI 与 I2C 通信接口。

3. UART 接收：同步、过采样与中点采样

接收比发送难，因为 RX 信号是异步输入，与 FPGA 时钟没有任何关系：

  1. 先同步：RX 引脚必须经过两级寄存器同步后才能使用，否则亚稳态会导致状态机跳到非法状态，见 跨时钟域处理。
  2. 检测起始位下降沿，之后等待半个位时间，在起始位中点确认电平仍为低（过滤毛刺）。
  3. 之后每隔一个位时间采样一次，正好落在每一位的中点，对时钟误差和边沿抖动的容忍度最大。
  4. 检查停止位：停止位不为高时报告帧错误，并丢弃该字节。
// 关键片段：同步 + 中点采样
(* ASYNC_REG = "TRUE" *) reg [1:0] rx_sync;
always @(posedge clk) rx_sync <= {rx_sync[0], rx_pin};
wire rx = rx_sync[1];

localparam integer HALF = DIV / 2;
// IDLE：检测到 rx 为低 → START，计数清零
// START：计数到 HALF 时 rx 仍为低 → DATA，否则判为毛刺回到 IDLE
// DATA：每计数到 DIV 采样一位，收满 8 位 → STOP
// STOP：计数到 DIV 时采样，为高则输出 data_valid，为低则报 frame_err

更稳健的做法是 16 倍过采样：每位采样 16 次，取中间 3 次多数表决，进一步抵抗噪声。

4. SPI 主机：模式与时钟边沿

SPI 主机需要产生 SCK，并按模式（CPOL/CPHA）在正确的边沿输出和采样数据。在 FPGA 内部，SCK 不作为时钟使用，而是由系统时钟分频产生的普通输出信号；“上升沿”“下降沿”实际上是计数器到达特定值时产生的使能脉冲：

// 系统时钟 100MHz，SCK = 100MHz / (2 × HALF_DIV)
// 模式 0（CPOL=0, CPHA=0）：SCK 空闲为低，前沿（上升沿）采样 MISO，后沿（下降沿）更新 MOSI
always @(posedge clk) begin
    if (sck_div_cnt == HALF_DIV - 1) begin
        sck_div_cnt <= 0;
        sck <= ~sck;
        if (!sck) begin                         // 即将产生上升沿：采样
            rx_shift <= {rx_shift[6:0], miso_sync};
        end else begin                          // 即将产生下降沿：移出下一位
            mosi <= tx_shift[7];
            tx_shift <= {tx_shift[6:0], 1'b0};
        end
    end else begin
        sck_div_cnt <= sck_div_cnt + 1'b1;
    end
end

要点：

  • 第一位数据的建立：模式 0 下，第一个上升沿之前 MOSI 就必须已经输出最高位，所以在拉低 CS 的同时预先输出第一位。
  • MISO 的采样时刻：高速 SPI（几十 MHz）时，从 SCK 输出到从机返回 MISO 存在往返延迟，可能需要延后半个周期采样，或者使用 IO 约束和 IDDR 精确控制。
  • SCK 不要作为内部时钟使用：如果 FPGA 是 SPI 从机，SCK 作为异步输入，常用做法是用系统时钟（远高于 SCK 频率）同步采样 SCK 和 MOSI，检测边沿后处理。

5. I2C 主机：三态与开漏

I2C 的 SDA 是双向开漏信号，在 FPGA 中用三态缓冲实现：只输出 0 或高阻，从不主动输出 1，高电平由外部上拉电阻产生。

// 顶层：SDA 为 inout 端口
assign sda = sda_oe ? 1'b0 : 1'bz;          // sda_oe = 1 时拉低，否则释放
assign scl = scl_oe ? 1'b0 : 1'bz;          // SCL 也用开漏实现，以支持时钟拉伸

// 读取 SDA / SCL 的实际电平：同样需要同步
(* ASYNC_REG = "TRUE" *) reg [1:0] sda_sync, scl_sync;
always @(posedge clk) begin
    sda_sync <= {sda_sync[0], sda};
    scl_sync <= {scl_sync[0], scl};
end
  • 三态只能在顶层实现：大多数 FPGA 内部没有三态总线，1'bz 应只出现在顶层端口上，子模块通过 sda_oe、sda_in 分开的信号与顶层连接。
  • 时钟拉伸：主机释放 SCL 后，要读回 SCL 实际电平，确认它真的变高了才继续，否则从机拉住时钟时会出错。
  • START / STOP 条件：SCL 为高期间 SDA 下降是 START、上升是 STOP；数据位只能在 SCL 为低时改变。
  • 约束引脚：在约束文件中为 SDA、SCL 开启内部上拉（PULLUP true）只适用于调试，板上仍应有外部上拉电阻。

完整的 I2C 主机设计实例（包括 ACK 检查、读写状态机和 CRC 校验），见 AHT20 IIC 读取实例。

6. 接口模块的设计规范

把接口做成可复用的模块，建议统一以下约定：

约定说明
统一系统时钟接口内部用一个系统时钟 + 使能节拍，不产生新的时钟域
参数化时钟频率、波特率、SPI 分频、数据位宽用 parameter 传入
握手接口数据输入用 valid / ready（或 start / busy），数据输出用 valid 脉冲
异步输入同步所有来自引脚的输入（RX、MISO、SDA）先经过两级同步
错误标志帧错误、NACK、超时等以单独的信号输出，便于上层统计
超时保护等待从机响应的状态都有超时计数，防止状态机卡死

7. 工作场景：FPGA 与 MCU 之间的通信通道

FPGA 采集或处理后的数据，经常需要交给 MCU 或上位机。常见方案的对比：

方案速率优点注意点
UART1 ~ 几 Mbps最简单，调试方便速率有限，需要自定义帧格式和校验
SPI（FPGA 为从机）10 ~ 几十 MbpsMCU 端硬件 SPI + DMA 即可读取FPGA 端需同步 SCK，高速时注意 MISO 返回时序
并行总线（FSMC / FMC）数十 MB/s像访问外部 SRAM 一样读写 FPGA 寄存器引脚多，需按 MCU 总线时序设计
QSPI / SDIO 类几十 MB/s引脚少速度快协议实现复杂度较高

工程上常把 FPGA 内部的功能设计成一组“寄存器”：控制寄存器、状态寄存器、数据 FIFO。MCU 通过 SPI 或并行总线按地址读写这些寄存器，FPGA 端只需要实现一个“总线 → 寄存器”的译码模块。这样 MCU 一侧的驱动代码结构清晰，FPGA 一侧新增功能也只是新增寄存器。

8. 串行接口检查清单

  • 接口是否使用统一的系统时钟加节拍使能，避免产生新的时钟域。
  • 所有异步输入（RX、MISO、SDA、SCL）是否经过两级同步后再使用。
  • UART 接收是否在位中点采样，起始位是否做了毛刺过滤，停止位错误是否上报。
  • SPI 模式是否与对端一致，第一位数据是否在首个时钟沿之前就已输出，高速时 MISO 采样时刻是否经过评估。
  • I2C 是否以开漏方式实现，三态是否只出现在顶层，是否支持时钟拉伸。
  • 波特率和分频系数是否参数化，误差是否核算过。
  • 所有等待响应的状态是否有超时，错误标志是否输出给上层。
