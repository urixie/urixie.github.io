Verilog Testbench仿真与调试

FPGA 设计不能只靠上板测试。Testbench 可以在仿真环境中给 DUT 提供时钟.复位和输入激励，观察输出是否符合预期。很多时序.状态机和协议问题，在上板前就应该通过仿真发现。

工程建议：每写一个有明确输入输出的模块，都至少写一个基础 Testbench。尤其是 ADC/SPI/IIC/UART/帧解析/FIFO/状态机这类模块，没有仿真就上板，后期排错成本会非常高。

1.Testbench基本结构

Testbench 本身不综合成硬件，只用于仿真。它通常没有端口，内部例化待测模块 DUT，然后产生输入激励。

`timescale 1ns/1ps

module tb_counter;

reg clk;
reg rst_n;
wire [7:0] cnt;

counter dut (
    .clk   (clk),
    .rst_n (rst_n),
    .cnt   (cnt)
);

endmodule

2.产生时钟和复位

仿真中最常见的激励是时钟和复位。时钟用 always 周期翻转，复位用 initial 控制释放时刻。

initial begin
    clk = 1'b0;
end

always #10 clk = ~clk; // 50MHz

initial begin
    rst_n = 1'b0;
    #100;
    rst_n = 1'b1;
end

3.输入激励

输入激励可以直接在 initial 中按时间推进，也可以封装成 task，让测试过程更清晰。

task send_pulse;
begin
    trig = 1'b1;
    @(posedge clk);
    trig = 1'b0;
    @(posedge clk);
end
endtask

initial begin
    trig = 1'b0;
    wait(rst_n == 1'b1);
    repeat (5) send_pulse();
    #1000;
    $finish;
end

4.波形输出

使用 Icarus Verilog.GTKWave 等工具时，可以输出 VCD 波形文件。其它 FPGA IDE 也有自己的波形查看器。

initial begin
    $dumpfile("tb_counter.vcd");
    $dumpvars(0, tb_counter);
end

5.$display调试

$display 可以在仿真控制台打印变量值，适合快速判断状态跳转.计数值和错误路径。

always @(posedge clk) begin
    if (data_valid) begin
        $display("time=%0t data=%h", $time, data);
    end
end

6.自检查Testbench

更好的 Testbench 不只是看波形，而是自动判断输出是否正确。这样改代码后可以快速回归验证。

if (cnt !== 8'd10) begin
    $display("ERROR: cnt expected 10, got %0d", cnt);
    $finish;
end else begin
    $display("PASS");
end

7.常见仿真问题

现象优先排查方向
波形全是 X复位没有释放.信号未初始化.分支未赋值
输出慢一拍时序逻辑寄存器更新延迟，确认是否符合设计
状态机不跳转跳转条件没有拉高.握手信号时序不对
仿真正确上板错误时序约束.跨时钟域.复位同步.外设真实时序
综合后行为不同不可综合语句.latch.阻塞/非阻塞误用

8.上板调试思路

上板调试时，可以使用 FPGA 厂商提供的逻辑分析仪工具抓内部信号，例如 SignalTap.ILA.安路或其它工具链中的在线调试功能。抓信号时要优先抓状态机状态.计数器.valid/ready.错误标志和外设接口关键线。

9.仿真检查清单

  • 是否产生了稳定时钟。
  • 复位时长是否足够。
  • 是否覆盖正常路径.异常路径和边界条件。
  • 是否检查输出结果，而不是只看波形。
  • Testbench 是否包含必要的超时退出。
  • 上板前是否确认时序约束和跨时钟域处理。
