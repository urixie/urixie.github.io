FPGA 时钟与时序约束

整理 FPGA 时序约束的核心概念与写法：建立与保持时间、时钟约束与生成时钟、异步时钟组、输入输出延迟、false path 与 multicycle 例外、时序报告解读，并给出一个 ADC 采集工程的完整约束示例。

1. 为什么必须写时序约束

在 FPGA 里，“功能仿真通过”只说明逻辑正确，不说明电路能在目标频率下稳定工作。真正决定电路能否工作的是时序：信号从一个寄存器出发，经过组合逻辑和布线，必须在下一个时钟沿到来之前稳定地到达下一个寄存器。

综合与布局布线工具会根据约束来优化电路、检查时序。没有约束，工具就不知道时钟有多快、输入数据什么时候到达，时序报告里看不到违例，并不代表电路没问题，只是没有检查。典型的后果是：低温正常、高温出错；这块板子正常、那块板子偶尔出错；改了一处无关的逻辑，另一处功能就坏了。

2. 建立时间与保持时间

寄存器在时钟沿采样数据，数据必须满足两个条件：

  • 建立时间（Setup）：数据在时钟沿到来之前必须稳定的最短时间。
  • 保持时间（Hold）：数据在时钟沿到来之后必须继续保持的最短时间。

对于同一时钟驱动的两个寄存器之间的路径：

建立时间裕量 Setup Slack = 时钟周期 + 时钟偏斜 - (Tco + 组合逻辑延迟 + 布线延迟) - Tsu
保持时间裕量 Hold Slack  = (Tco + 组合逻辑延迟 + 布线延迟) - 时钟偏斜 - Th

Slack 为正表示满足要求，为负表示违例。几个直观的结论：

  • 建立时间违例说明路径太慢，降低频率或减少路径上的逻辑可以解决。
  • 保持时间违例说明路径太快，与频率无关，降低频率不能解决。工具一般会自动插入延迟修复保持违例，同一时钟域内很少出现，多见于时钟结构异常或 IO 约束错误。

3. 时钟约束

所有约束中最重要的是时钟约束。下面以 Xilinx 的 XDC（与业界通用的 SDC 语法基本一致）为例：

# 1. 主时钟：来自引脚的 50MHz 晶振，周期 20ns
create_clock -name sys_clk -period 20.000 [get_ports clk_50m]

# 2. 由 PLL / MMCM 产生的时钟：Vivado 会根据 IP 配置自动推导，通常不需要手写
#    对于用逻辑分频产生的时钟（不推荐），需要手动声明生成时钟
create_generated_clock -name clk_div2 -source [get_ports clk_50m] -divide_by 2 [get_pins div_reg/Q]

# 3. 互相异步的时钟组：告诉工具不要分析它们之间的路径（跨时钟域由设计保证）
set_clock_groups -asynchronous -group [get_clocks sys_clk] -group [get_clocks -include_generated_clocks eth_rx_clk]

要点：

  • 每个时钟输入引脚都要 create_clock，包括外部芯片送来的随路时钟（如以太网 PHY 的 RX_CLK、ADC 的数据时钟）。
  • PLL 输出时钟由工具自动推导，只要输入时钟约束正确。手写会产生重复约束。
  • 尽量不要用逻辑分频产生时钟：逻辑产生的时钟不走全局时钟网络，偏斜大、难以约束。需要低频动作时，用时钟使能代替，见 组合逻辑与时序逻辑。
  • 异步时钟组必须声明：否则工具会尝试分析两个无关时钟之间的路径，报出大量虚假违例，掩盖真正的问题；但声明后工具不再检查这些路径，跨时钟域必须在设计上正确处理，见 跨时钟域处理。

4. 输入输出约束

时钟约束只覆盖 FPGA 内部的寄存器到寄存器路径。FPGA 与外部芯片之间的数据，还需要告诉工具外部的延迟是多少：

# 输入：外部 ADC 在 adc_clk 上升沿后 2~5ns 输出数据（数据手册给出的 Tco 范围，加上板级走线延迟）
create_clock -name adc_clk -period 10.000 [get_ports adc_clk]
set_input_delay -clock adc_clk -max 5.000 [get_ports {adc_data[*]}]
set_input_delay -clock adc_clk -min 2.000 [get_ports {adc_data[*]}]

# 输出：外部 DAC 要求数据在时钟沿前 3ns 建立、沿后 1ns 保持
set_output_delay -clock dac_clk -max 3.000 [get_ports {dac_data[*]}]
set_output_delay -clock dac_clk -min -1.000 [get_ports {dac_data[*]}]
  • -max 用于建立时间检查，-min 用于保持时间检查，两者都要写。
  • 数值来自外部芯片数据手册的时序参数，再加上 PCB 走线延迟（约 6ps/mm，按经验估算即可）。
  • 对于低速、不关心时序的信号（按键、LED、慢速配置引脚），可以用 set_false_path 排除，避免产生无意义的违例。

IO 寄存器：把输入数据的第一级寄存器和输出数据的最后一级寄存器放进 IOB（输入输出块）中，可以让 IO 时序与内部布局无关、每次编译都一致。Vivado 中使用 set_property IOB TRUE [get_ports ...] 或在代码中添加 (* IOB = "TRUE" *) 属性。

5. 时序例外：false path 与 multicycle

有些路径不需要在一个时钟周期内完成，或者根本不需要分析：

# 伪路径：复位同步器的异步输入、静态配置寄存器（上电配置后不再变化）
set_false_path -from [get_ports rst_n]
set_false_path -to [get_cells cfg_static_reg*]

# 多周期路径：数据每 2 个时钟周期才更新一次（由使能信号控制）
set_multicycle_path 2 -setup -from [get_cells mul_a_reg*] -to [get_cells mul_q_reg*]
set_multicycle_path 1 -hold  -from [get_cells mul_a_reg*] -to [get_cells mul_q_reg*]

时序例外用错比不用更危险：把一条真实存在的关键路径设为 false path，工具就不再检查它，时序报告“全部通过”，但电路在板上随机出错。每一条例外都应该有明确的理由，并在约束文件中写注释说明。设置多周期路径时，保持时间的倍数通常要同时调整（上例中的 -hold 1），否则保持检查会被推到错误的时钟沿。

6. 读懂时序报告

布局布线后打开时序报告，先看总览：

指标含义要求
WNS（Worst Negative Slack）最差的建立时间裕量≥ 0
TNS（Total Negative Slack）所有违例路径裕量之和= 0
WHS（Worst Hold Slack）最差的保持时间裕量≥ 0
THS（Total Hold Slack）所有保持违例之和= 0
未约束的路径没有被任何时钟约束覆盖的路径应为 0 或都有合理解释

“未约束路径”和“时钟交互报告”同样重要。Vivado 中运行 report_clock_interaction 可以看到每对时钟之间的路径是否被正确约束（安全、异步、未约束）；check_timing 会列出没有时钟的寄存器、没有输入延迟的端口等问题。时序全部通过之前，应先确保这些检查是干净的。

打开一条违例路径，重点看：起点和终点分别是哪个寄存器、经过了几级逻辑（Logic Levels）、逻辑延迟和布线延迟各占多少、扇出有多大。这些信息决定了如何优化，见 时序收敛方法。

7. 工作场景：为一个 ADC 采集工程编写约束

工程：50MHz 晶振输入，MMCM 产生 100MHz 系统时钟；外部并行 ADC 随路输出 80MHz 时钟和 12 位数据；UART 和 LED 为低速信号。

## 时钟
create_clock -name clk_50m -period 20.000 [get_ports clk_50m]
create_clock -name adc_clk -period 12.500 [get_ports adc_dco]

## 系统时钟（MMCM 输出，自动推导）与 ADC 时钟互相异步，数据通过异步 FIFO 跨时钟域
set_clock_groups -asynchronous \
    -group [get_clocks -include_generated_clocks clk_50m] \
    -group [get_clocks adc_clk]

## ADC 数据输入：按 ADC 手册的输出延迟 + 走线延迟估算
set_input_delay -clock adc_clk -max 4.200 [get_ports {adc_d[*]}]
set_input_delay -clock adc_clk -min 1.000 [get_ports {adc_d[*]}]

## 低速 IO：不做时序检查
set_false_path -from [get_ports uart_rx]
set_false_path -to   [get_ports {uart_tx led[*]}]
set_false_path -from [get_ports rst_n]

## 引脚与电平（示例）
set_property -dict {PACKAGE_PIN E3 IOSTANDARD LVCMOS33} [get_ports clk_50m]

写完约束后的检查顺序：check_timing 无警告 → 时钟交互报告中没有“未约束”的时钟对 → WNS / WHS 均为正。三者都满足，时序结果才可信。

8. 时序约束检查清单

  • 每个时钟输入（包括外部随路时钟）是否都有 create_clock，周期是否与实际一致。
  • 是否避免了逻辑分频时钟；确实需要时是否声明了生成时钟。
  • 异步时钟之间是否声明了时钟组，跨时钟域是否在设计上有同步处理。
  • 与外部芯片的高速接口是否写了 -max 和 -min 的输入输出延迟，数值是否有手册依据。
  • 每一条 false path / multicycle path 是否有明确理由和注释。
  • check_timing 和时钟交互报告是否干净，是否存在未约束路径。
  • WNS、TNS、WHS、THS 是否全部满足，IO 关键寄存器是否放进了 IOB。
