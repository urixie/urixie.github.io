Vivado 工程流程与在线调试

整理 Vivado 的设计流程与工程实践：综合实现各阶段、工程模式与 Tcl 非工程模式、IP 核与 Block Design、关键警告处理、ILA 与 VIO 在线调试、比特流下载与配置 Flash 固化，以及新工程的推进顺序。

1. Vivado 设计流程概览

Vivado 是 Xilinx（现 AMD）7 系列及之后器件的开发工具。一个工程从源码到烧录，依次经过：

RTL 源码 / IP / Block Design
   │  综合 synth_design：RTL → 网表（LUT、FF、DSP、BRAM 等原语）
   ▼
   │  实现 implementation
   │    opt_design      逻辑优化
   │    place_design    布局
   │    phys_opt_design 物理优化（复制高扇出、重定时等）
   │    route_design    布线
   ▼
生成比特流 write_bitstream → .bit（下载到 FPGA）/ .bin、.mcs（烧写配置 Flash）

每一步之后都可以打开对应的设计查看报告：综合后看资源使用和关键警告，实现后看时序和功耗。不要只看最后有没有生成 bit 文件。

2. 工程模式与非工程模式

方式特点适用
工程模式（GUI）图形界面管理源文件和流程，自动保存中间结果学习、小型工程、调试分析
非工程模式（Tcl 脚本）用脚本描述整个流程，所有步骤可复现团队协作、版本管理、持续集成

Vivado 的工程文件夹包含大量自动生成的文件，不适合直接放进 Git。推荐的做法是只提交源码、约束、IP 配置文件（.xci）和一个重建工程的 Tcl 脚本：

# build.tcl：从源码重建工程并完成实现（非工程模式）
read_verilog [glob ./src/*.v]
read_xdc ./constr/top.xdc
read_ip ./ip/fifo_adc/fifo_adc.xci
synth_design -top top -part xc7a35tcsg324-1
opt_design
place_design
phys_opt_design
route_design
report_timing_summary -file ./reports/timing.rpt
report_utilization    -file ./reports/util.rpt
write_bitstream -force ./out/top.bit

运行方式：vivado -mode batch -source build.tcl。在 GUI 中也可以通过 File → Project → Write Tcl 导出重建工程的脚本。

3. IP 核与 Block Design

IP 核：时钟（Clocking Wizard / MMCM）、FIFO、BRAM、乘法器、FIR、DDR 控制器（MIG）等，都可以通过 IP Catalog 配置生成。几个工程习惯：

  • IP 配置文件（.xci）纳入版本管理，生成的输出产品不提交，由工具重新生成。
  • 升级 Vivado 版本后，IP 可能被锁定（locked），需要按提示升级（Upgrade IP），并重新检查配置。
  • 优先使用 XPM 宏（xpm_fifo_async、xpm_cdc_single、xpm_memory_sdpram）：它们以代码形式实例化，不需要生成 IP，便于版本管理，并且自带正确的 CDC 约束。

Block Design：用图形化方式连接 IP，特别适合包含处理器（MicroBlaze 软核、Zynq 的 ARM 硬核）和 AXI 总线的系统。工程习惯：

  • 自定义逻辑尽量写成独立的 RTL 模块，通过 AXI 接口或模块引用（Add Module）加入 Block Design，不要把大量逻辑连线做在图里。
  • 地址编辑器（Address Editor）中为每个 AXI 外设分配地址，软件中的寄存器地址以此为准。
  • Block Design 同样可以导出为 Tcl（write_bd_tcl），用于版本管理和重建。

4. 关键警告不要忽略

综合和实现会产生大量消息，其中 Critical Warning 必须逐条处理。最常见、也最危险的几类：

警告类型含义后果
约束找不到对象（No ports matched）XDC 中的端口名或单元名写错约束没有生效，时序和引脚分配可能都不对
引脚未分配 / IOSTANDARD 未设置端口没有约束到具体引脚生成比特流时报错，或引脚被随机分配
组合环路（combinational loop）组合逻辑输出反馈到自己的输入电路振荡或行为不可预测
推断出锁存器（latch）组合 always 块中有分支没有赋值时序难以分析，功能可能不符合预期
多驱动（multi-driven net）一个信号在多个 always 块或 assign 中被驱动综合失败或结果错误
时钟走了普通布线时钟信号没有使用全局时钟网络时钟偏斜大，时序难以收敛

锁存器和多驱动问题的成因与写法规范，见 组合逻辑与时序逻辑。

5. 在线调试：ILA 与 VIO

仿真无法覆盖所有真实情况（外部器件的实际行为、真实的数据、偶发事件），上板后需要在线观察内部信号。Vivado 提供：

  • ILA（Integrated Logic Analyzer）：把内部信号连接到片上逻辑分析仪，用 BRAM 存储波形，通过 JTAG 在 Vivado 中查看，支持复杂的触发条件。
  • VIO（Virtual Input/Output）：在 Vivado 界面中实时读取内部信号的值，或者驱动内部信号（相当于虚拟的按键和指示灯），适合调试时手动给使能、切换模式。

两种插入 ILA 的方式：

// 方式一：在代码中标记要观察的信号，综合后通过 Set Up Debug 向导插入 ILA
(* mark_debug = "true" *) reg [3:0]  state;
(* mark_debug = "true" *) reg [11:0] adc_data;

// 方式二：直接实例化 ILA IP，适合需要精确控制采样时钟和探针的场景
ila_0 u_ila (
    .clk    (clk_100m),
    .probe0 (state),
    .probe1 (adc_data),
    .probe2 (fifo_full)
);

ILA 使用技巧：

  • 采样时钟要选对：ILA 的时钟应与被观察信号在同一时钟域，否则看到的波形没有意义。
  • 深度与资源：采样深度 × 探针总位宽决定 BRAM 用量，观察信号要有选择，不要一次连上几百位。
  • 用触发捕捉偶发事件：例如触发条件设为“FIFO 溢出 = 1”或“状态机进入错误状态”，并设置触发位置在中间，可以同时看到事件前后的波形。
  • mark_debug 会阻止优化：被标记的信号不会被综合优化掉，可能影响时序和资源，调试完成后应移除。

6. 下载与固化

  • 下载 .bit 到 FPGA：通过 JTAG 直接配置，掉电后丢失，用于调试。
  • 烧写配置 Flash：生成 .bin 或 .mcs 文件，通过 Hardware Manager 添加配置存储器（选择板上 Flash 的具体型号）后烧写，FPGA 上电时自动从 Flash 加载。
  • 加快上电加载：在约束中设置配置速率和 SPI 位宽（如 BITSTREAM.CONFIG.SPI_BUSWIDTH 4、BITSTREAM.CONFIG.CONFIGRATE 33），可以显著缩短上电后的配置时间，前提是板上 Flash 支持对应模式。
  • 压缩比特流：BITSTREAM.GENERAL.COMPRESS TRUE 可以减小比特流体积、缩短加载时间。
set_property BITSTREAM.GENERAL.COMPRESS TRUE [current_design]
set_property BITSTREAM.CONFIG.SPI_BUSWIDTH 4 [current_design]
set_property BITSTREAM.CONFIG.CONFIGRATE 33 [current_design]
set_property CONFIG_VOLTAGE 3.3 [current_design]
set_property CFGBVS VCCO [current_design]

CONFIG_VOLTAGE 和 CFGBVS 描述配置 Bank 的电压，没有设置时会产生警告，并且可能影响配置引脚的电平检查。

7. 工作场景：一个新工程的检查顺序

拿到一块新板子、建立一个新工程时，推荐的推进顺序：

  1. 最小工程：时钟输入 → MMCM → 计数器驱动 LED 闪烁。确认时钟引脚、电平标准、MMCM 锁定都正常，这一步就能发现大部分板级问题。
  2. 约束与报告：引脚、时钟约束齐全，check_timing 和关键警告清零，时序报告满足。
  3. 逐个加入接口：UART 回环 → 外部 ADC / DAC → 存储器。每加入一个模块，先仿真，再上板用 ILA 验证。
  4. 脚本化：工程稳定后导出 Tcl 构建脚本，纳入版本管理，团队成员和 CI 都用同一个脚本构建。
  5. 固化：烧写配置 Flash，测试上电自动加载，确认配置时间满足系统上电时序要求。
  6. 记录：每次发布保存比特流、时序报告和资源报告，标注对应的代码版本。

8. Vivado 工程检查清单

  • 工程是否可以通过 Tcl 脚本从源码重建，版本管理中是否只包含源码、约束和 IP 配置。
  • 所有 Critical Warning 是否逐条处理，特别是约束找不到对象、锁存器、组合环路、多驱动。
  • 引脚和电平标准是否完整约束，配置 Bank 电压（CONFIG_VOLTAGE、CFGBVS）是否设置。
  • 时钟是否使用全局时钟资源，跨时钟域是否使用 XPM CDC 宏或异步 FIFO。
  • ILA 的采样时钟是否正确，调试结束后是否移除了不必要的 mark_debug。
  • 配置 Flash 的型号、位宽、速率设置是否正确，上电加载时间是否满足要求。
  • 每次发布是否保存了比特流、时序报告和资源报告，并对应到代码版本。
