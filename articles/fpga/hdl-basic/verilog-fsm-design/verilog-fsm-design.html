Verilog 状态机设计方法

状态机是 FPGA 设计中最常用的控制结构。协议解析、ADC 采样时序、SPI/IIC 控制、帧接收、按键消抖、启动流程控制，几乎都可以用状态机描述。状态机的核心是：当前状态、状态跳转条件、下一状态和输出逻辑。

状态机不是为了让代码显得复杂，而是为了把流程拆清楚。只要一个模块存在多个阶段，并且不同阶段行为不同，就应该考虑状态机。

1. 状态机的基本组成

  • 当前状态：state，记录现在处于哪个阶段。
  • 下一状态：next_state，组合逻辑计算下一步去哪里。
  • 跳转条件：输入事件、计数结束、握手完成、超时等。
  • 输出逻辑：根据状态或跳转条件产生控制信号。

2. 状态编码

状态通常用 localparam 定义，避免在代码里直接写魔法数字。

localparam S_IDLE  = 2'd0;
localparam S_START = 2'd1;
localparam S_WAIT  = 2'd2;
localparam S_DONE  = 2'd3;

reg [1:0] state;
reg [1:0] next_state;

小型状态机可以用二进制编码；速度要求高、状态较多时，也可以考虑 one-hot 编码。具体由综合工具和目标 FPGA 资源决定。

3. 三段式状态机

三段式状态机把“状态寄存器”“下一状态组合逻辑”“输出逻辑”分开，结构清晰，适合大多数工程代码。

// 第一段：状态寄存器
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        state <= S_IDLE;
    else
        state <= next_state;
end

// 第二段：下一状态组合逻辑
always @(*) begin
    next_state = state;
    case (state)
        S_IDLE: begin
            if (start)
                next_state = S_START;
        end
        S_START: begin
            next_state = S_WAIT;
        end
        S_WAIT: begin
            if (done)
                next_state = S_DONE;
        end
        S_DONE: begin
            next_state = S_IDLE;
        end
        default: begin
            next_state = S_IDLE;
        end
    endcase
end

// 第三段：输出逻辑
always @(*) begin
    busy = 1'b0;
    case (state)
        S_START,
        S_WAIT: busy = 1'b1;
        default: busy = 1'b0;
    endcase
end

4. 一段式、两段式、三段式怎么选

写法特点建议
一段式状态跳转和输出写在一个时序 always 中小状态机可用，但复杂后不易维护
两段式状态寄存器一段，组合逻辑一段常用，但输出逻辑要注意毛刺
三段式状态寄存器、跳转逻辑、输出逻辑分开推荐作为工程默认写法

5. Moore 与 Mealy

Moore 状态机输出只和当前状态有关；Mealy 状态机输出和当前状态、输入条件都有关。Moore 更稳定，Mealy 响应更快，但要注意组合路径和毛刺。

// Moore：输出只看 state
assign busy = (state == S_WAIT);

// Mealy：输出和 state、输入都有关
assign fire = (state == S_WAIT) && data_valid;

6. 状态机常见错误

  • 没有 default 分支，异常状态无法恢复。
  • 组合逻辑中没有默认赋值，推断 latch。
  • 状态跳转条件没有打一拍，导致跨时钟域问题。
  • 输出信号毛刺影响下游模块。
  • 状态太多但命名不清晰，后期难以维护。

7. 状态编码的工程选择

编码特点适用
二进制（binary）状态寄存器位数最少（N 个状态需要 ⌈log2 N⌉ 位）状态较少、资源紧张
独热码（one-hot）每个状态一个触发器，任意时刻只有一位为 1FPGA 中状态较多、速度要求高时常用，状态译码逻辑简单
格雷码（gray）相邻状态只变化一位状态按顺序线性跳转的场合

FPGA 触发器资源丰富，独热码的“多用触发器、少用组合逻辑”通常更有利于时序。实际上，Vivado 等综合工具会自动识别状态机并重新选择编码（FSM Extraction），代码中写的 localparam 编码不一定是最终结果。需要固定编码时，可以用属性指定：

(* fsm_encoding = "one_hot" *) reg [2:0] state;    // Vivado：可选 one_hot、sequential、gray、none 等

综合报告中会列出识别到的状态机及其最终编码，修改状态机后可以确认一下。

8. 安全状态机：从非法状态恢复

3 位状态寄存器可以表示 8 个状态，如果只用了 5 个，剩下 3 个就是非法状态。正常情况下状态机不会进入非法状态，但单粒子翻转（高海拔、辐射环境）、时钟毛刺、电源干扰都可能让寄存器翻转。

  • case 中写 default 分支，让非法状态回到 IDLE 或专门的错误状态。
  • 注意：综合工具可能把“永远不会到达”的 default 分支优化掉。对可靠性有要求的设计，需要使用工具的安全状态机选项（如 Vivado 的 fsm_safe_state 属性，可设置为 reset_state、default_state 等）保留恢复逻辑。
(* fsm_safe_state = "reset_state" *) reg [2:0] state;

9. 寄存输出，消除毛刺

三段式状态机的第三段如果用组合逻辑译码输出（assign cs_n = (state != S_XFER);），状态切换的瞬间各位翻转时间不一致，输出可能出现很窄的毛刺。毛刺在 FPGA 内部同步电路中一般无害（会在下个时钟沿前稳定），但送到外部芯片的控制信号（片选、写使能、复位）出现毛刺会导致误操作。

推荐对关键输出使用时序逻辑，并根据下一状态产生，使输出与状态在同一拍变化：

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cs_n <= 1'b1;
    else
        cs_n <= (next_state != S_XFER);    // 用 next_state 译码，寄存后与 state 同步变化
end

10. 状态机与计数器配合：超时和固定时长

很多状态需要“停留固定时间”或“等待事件，但不能无限等”。推荐在状态机外维护一个计数器，在进入新状态时清零：

// 进入新状态时计数器清零，停留期间递增
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)                    state_cnt <= 0;
    else if (state != next_state)  state_cnt <= 0;
    else                           state_cnt <= state_cnt + 1'b1;
end

// 跳转逻辑中使用
S_WAIT_ACK: begin
    if (ack)                              next_state = S_DONE;
    else if (state_cnt == TIMEOUT_CYCLES) next_state = S_ERROR;   // 超时
    else                                  next_state = S_WAIT_ACK;
end

所有“等待外部响应”的状态都应该有超时出口。没有超时的状态机，只要外部器件一次不响应，就会永远卡住，只能复位。

11. 工作场景：带超时与重试的命令应答状态机

FPGA 通过 UART 向一个外部模块发送命令并等待应答：发送 → 等待应答（最长 50ms）→ 超时则重发，最多 3 次 → 仍失败则进入错误状态并上报。

localparam S_IDLE = 3'd0, S_SEND = 3'd1, S_WAIT = 3'd2, S_DONE = 3'd3, S_ERROR = 3'd4;
localparam integer TIMEOUT = CLK_HZ / 1000 * 50;     // 50ms
localparam integer MAX_RETRY = 3;

always @(*) begin
    next_state = state;
    case (state)
        S_IDLE:  if (cmd_start)               next_state = S_SEND;
        S_SEND:  if (tx_done)                 next_state = S_WAIT;
        S_WAIT:  if (rx_ack)                  next_state = S_DONE;
                 else if (state_cnt == TIMEOUT)
                     next_state = (retry_cnt == MAX_RETRY - 1) ? S_ERROR : S_SEND;
        S_DONE:                               next_state = S_IDLE;
        S_ERROR: if (err_clear)               next_state = S_IDLE;
        default:                              next_state = S_IDLE;
    endcase
end

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)                                  retry_cnt <= 0;
    else if (state == S_IDLE)                    retry_cnt <= 0;
    else if (state == S_WAIT && next_state == S_SEND) retry_cnt <= retry_cnt + 1'b1;
end

这个结构把“正常流程、超时、重试、错误上报、错误清除”都显式地表达在状态图中，仿真时可以逐条验证：正常应答、第 2 次重试成功、3 次都超时进入错误状态、错误清除后能重新开始。软件中的同类设计思路见 状态机与事件驱动设计。

12. 工程检查清单

  • 状态名是否能表达真实流程。
  • 复位后状态是否确定。
  • 所有状态是否都有跳转出口。
  • 是否有 default 恢复到安全状态。
  • 输出信号是否可能出现毛刺。
  • 跨时钟域输入是否先同步。
  • 仿真是否覆盖异常状态和超时路径。
  • 状态编码是否符合时序与资源需求，综合报告中的最终编码是否确认过。
  • 可靠性要求高的设计，是否使用安全状态机选项保留非法状态恢复逻辑。
  • 送往外部芯片的控制信号是否寄存输出（用 next_state 译码），避免毛刺。
  • 所有等待外部响应的状态是否有超时出口和重试上限。
