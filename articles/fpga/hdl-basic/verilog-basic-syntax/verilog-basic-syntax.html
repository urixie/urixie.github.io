Verilog 基础语法与硬件描述思维

Verilog 不是普通软件语言，而是硬件描述语言。写 Verilog 的重点不是“程序一行一行执行”，而是描述电路结构、寄存器行为、组合逻辑和时序逻辑。本文从最基础的语法开始，建立面向 FPGA 的硬件描述思维。

初学 Verilog 最容易犯的错误，是把它当 C 语言写。C 语言描述的是 CPU 上顺序执行的指令，Verilog 描述的是并行存在的硬件电路。你写下的每个 always、assign、寄存器和连线，最终都要能对应到硬件结构。

1. Verilog 工程的基本单位：module

module 是 Verilog 的基本设计单元，可以理解为一个硬件模块。模块有输入、输出和内部逻辑，综合后可能变成组合逻辑、触发器、RAM、DSP 或其它 FPGA 资源。 

module led_blink (
    input  wire clk,
    input  wire rst_n,
    output reg  led
);

endmodule

上面这个模块有一个时钟 clk、一个低有效复位 rst_n 和一个 LED 输出 led。端口方向决定信号从模块外进入还是从模块内输出。

2. wire 与 reg

wire 更像连线，常用于连续赋值和模块端口连接；reg 表示在过程块中被赋值的变量，综合后不一定都是寄存器，是否变成寄存器取决于 always 块写法。 

wire a_and_b;
reg  data_valid;

assign a_and_b = a & b;
  • assign 左侧通常是 wire。
  • always 块内赋值的信号通常声明为 reg。
  • reg 不等于一定综合成触发器。

3. assign 连续赋值

assign 描述组合逻辑。只要右侧输入信号变化，左侧输出就会跟着变化，类似一根持续存在的硬件连线加组合门电路。 

assign y = (sel == 1'b1) ? a : b;
assign sum = data0 + data1;

4. always 块

always 用于描述过程逻辑。根据敏感列表不同，可以描述组合逻辑，也可以描述时序逻辑。 

// 组合逻辑
always @(*) begin
    y = sel ? a : b;
end

// 时序逻辑
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end

always @(*) 常用于组合逻辑；always @(posedge clk) 常用于触发器和寄存器逻辑。

5. 阻塞赋值与非阻塞赋值

阻塞赋值使用 =，语句按顺序立即更新；非阻塞赋值使用 <=，通常在时钟边沿统一更新。工程中建议遵循：组合逻辑用阻塞赋值，时序逻辑用非阻塞赋值。 

// 组合逻辑推荐用 =
always @(*) begin
    y = a & b;
end

// 时序逻辑推荐用 <=
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 1'b0;
    else
        q <= d;
end
初学阶段不要在同一个 always 块中混用复杂的阻塞和非阻塞赋值。尤其是时序逻辑中误用阻塞赋值，仿真行为和综合后硬件理解都容易出错。

6. 参数化设计

parameter 可以让模块更容易复用。例如计数器位宽、FIFO 深度、数据总线宽度都适合参数化。 

module counter #(
    parameter WIDTH = 16
)(
    input  wire             clk,
    input  wire             rst_n,
    output reg [WIDTH-1:0]  cnt
);

always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        cnt <= {WIDTH{1'b0}};
    else
        cnt <= cnt + 1'b1;
end

endmodule

7. 位宽、常量与有符号数

Verilog 中大量隐蔽的 bug 来自位宽：赋值时高位被悄悄截断、运算结果被悄悄扩展，综合工具通常只给一条警告。

常量要写明位宽和进制：不带位宽的常量（如 255）默认是 32 位有符号数，参与运算或拼接时容易得到意外结果。

localparam [7:0] MAX_CNT = 8'd200;     // 推荐：位宽 + 进制
wire [15:0] a = 16'hFFFF;
wire [7:0]  b = a;                     // 截断：b = 8'hFF，只保留低 8 位（会有警告）
wire [15:0] c = {8'h00, b};            // 显式零扩展
wire [3:0]  d = {4{1'b1}};             // 复制拼接：4'b1111

运算结果的位宽：加法结果需要多 1 位才能容纳进位，乘法结果的位宽是两个操作数位宽之和。目标位宽不够时，高位直接丢失：

wire [7:0]  x, y;
wire [7:0]  sum_bad  = x + y;          // 200 + 100 = 300，截断为 44
wire [8:0]  sum_ok   = x + y;          // 9 位，结果正确
wire [15:0] prod     = x * y;          // 8 位 × 8 位 = 16 位

有符号数：默认情况下 reg / wire 都是无符号的。需要处理负数（ADC 的二进制补码输出、滤波器系数）时，必须显式声明 signed：

wire signed [11:0] adc_raw;            // ADC 补码输出
wire signed [15:0] gain = 16'sd3;
wire signed [27:0] scaled = adc_raw * gain;      // 两个操作数都是 signed，结果才是有符号乘法
wire signed [11:0] half = adc_raw >>> 1;         // 算术右移，保留符号位

一个表达式中只要有一个操作数是无符号的，整个表达式就按无符号计算，这与 C 语言的“有符号转无符号”问题类似（参见 整数运算、溢出与定点数）。混合运算时用 $signed() 显式转换，并在仿真中用负数验证。

8. 可综合与不可综合

Verilog 既能描述硬件，也能写仿真激励，二者使用的语法子集不同。写设计代码时只能使用可综合的部分：

语法设计代码中说明
assign、always @(*)、always @(posedge clk)可综合硬件描述的主体
for 循环可综合（循环次数必须固定）综合时展开为多份并行硬件，不是“循环执行”
initial一般不可综合部分 FPGA 工具支持用它给寄存器赋初值，但不具可移植性
#10 延时不可综合，被忽略硬件中没有“等 10ns”，延时要用计数器实现
$display、$finish不可综合仅用于仿真
while、forever、不固定次数的循环不可综合无法确定硬件规模
real 类型、除法（非 2 的幂）通常不可综合或资源巨大除法应改为乘以倒数或使用 IP

最需要警惕的是 for 循环：在软件里它代表“执行 N 次”，在硬件里它代表“复制 N 份电路”。一个 1024 次的 for 循环会生成 1024 份逻辑，而不是用 1024 个周期完成。

9. generate、function 与 task

generate：按参数批量生成重复的硬件结构，例如多通道处理、多位同步器：

genvar i;
generate
    for (i = 0; i < CH_NUM; i = i + 1) begin : g_ch
        channel_proc #(.DW(12)) u_ch (
            .clk   (clk),
            .din   (adc_data[i*12 +: 12]),      // +: 表示从 i*12 开始取 12 位
            .dout  (proc_data[i*16 +: 16])
        );
    end
endgenerate

function：封装一段可复用的组合逻辑，例如 CRC 计算、格雷码转换、饱和截位。function 不能包含时序控制（@、#），每次调用都会生成一份组合电路。

task：主要用于 Testbench，封装一段带时序的激励过程，例如“发送一个 UART 字节”，见 Testbench 仿真与调试。

10. 多驱动、inout 与三态

一个信号只能有一个驱动源：同一个 reg 只能在一个 always 块中赋值，同一个 wire 只能有一个 assign。在两个 always 块中给同一个信号赋值，仿真时结果取决于执行顺序，综合时直接报多驱动错误。

// 错误：cnt 被两个 always 块驱动
always @(posedge clk) if (clr) cnt <= 0;
always @(posedge clk) if (inc) cnt <= cnt + 1;

// 正确：同一个信号的所有赋值条件写在一个 always 块里，用优先级表达逻辑
always @(posedge clk)
    if (clr)      cnt <= 0;
    else if (inc) cnt <= cnt + 1'b1;

三态只在顶层使用：FPGA 内部没有三态总线，1'bz 只应出现在连接外部引脚的顶层端口上（如 I2C 的 SDA）。子模块之间应使用分开的“输出数据 + 输出使能 + 输入数据”三个信号。

11. 工作场景：一个规范的 LED 呼吸灯模块

把本文的规则组合成一个完整的小模块：参数化、位宽明确、单一驱动、计数器使能代替分频时钟。

module led_breath #(
    parameter CLK_HZ   = 50_000_000,
    parameter PWM_BITS = 8,                      // 256 级亮度
    parameter STEP     = 100                     // 每 STEP 个 PWM 周期调整一次亮度
) (
    input  wire clk,
    input  wire rst_n,
    output reg  led
);
    // PWM 计数器：约 20kHz，避免肉眼可见闪烁
    localparam integer PWM_DIV = CLK_HZ / (20_000 * (1 << PWM_BITS));
    reg [15:0]         div_cnt;
    reg [PWM_BITS-1:0] pwm_cnt;
    reg [PWM_BITS-1:0] duty;
    reg                dir;                      // 1：渐亮，0：渐暗
    reg [7:0]          step_cnt;
    wire               pwm_tick = (div_cnt == PWM_DIV - 1);
    wire               period_end = pwm_tick && (pwm_cnt == {PWM_BITS{1'b1}});

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n) begin
            div_cnt <= 0; pwm_cnt <= 0; duty <= 0; dir <= 1'b1; led <= 1'b0; step_cnt <= 0;
        end else begin
            div_cnt <= pwm_tick ? 16'd0 : div_cnt + 1'b1;
            if (pwm_tick) pwm_cnt <= pwm_cnt + 1'b1;
            if (period_end) step_cnt <= (step_cnt == STEP - 1) ? 8'd0 : step_cnt + 1'b1;
            if (period_end && step_cnt == STEP - 1) begin    // 每 STEP 个 PWM 周期调整一次占空比
                if (dir && duty == {PWM_BITS{1'b1}}) dir <= 1'b0;
                else if (!dir && duty == 0)       dir <= 1'b1;
                else duty <= dir ? duty + 1'b1 : duty - 1'b1;
            end
            led <= (pwm_cnt < duty);             // 寄存输出，避免毛刺
        end
    end
endmodule

50MHz 时钟下 PWM_DIV = 9，一个 PWM 周期为 9 × 256 = 2304 个时钟（约 46us，约 21.7kHz）。亮度从 0 到最大再到 0 共 510 步，每步 100 个 PWM 周期，一个呼吸周期约 510 × 100 × 46us ≈ 2.4 秒。所有动作都在同一个时钟下通过 pwm_tick、period_end 使能完成，没有产生新的时钟。

12. 基础编码检查清单

  • 模块端口方向是否清晰。
  • 组合逻辑是否覆盖所有分支，避免锁存器。
  • 时序逻辑是否统一使用非阻塞赋值。
  • 复位极性是否统一，例如 rst_n 表示低有效。
  • 位宽是否明确，避免无意识截断或扩展。
  • 参数化模块是否在边界值下验证过。
  • 常量是否写明位宽和进制，加法、乘法结果的位宽是否足够。
  • 处理负数时是否声明了 signed，混合运算是否用 $signed() 显式转换。
  • 设计代码中是否只使用可综合语法，for 循环是否清楚会被展开为并行硬件。
  • 每个信号是否只有一个驱动源，三态是否只出现在顶层端口。
