嵌入式 C 位运算与寄存器访问

整理驱动开发中的位运算与寄存器访问：常用位操作宏、volatile 寄存器映射、读改写风险、写 1 清零与读清零寄存器、原子置位寄存器与位带、多位字段操作、字节序打包、常用位技巧与位图，并给出一个可靠的 GPIO 驱动示例。

1. 为什么寄存器操作离不开位运算

外设寄存器通常是 32 位宽，但每一位或每几位代表不同含义：使能位、模式字段、中断标志、分频系数。驱动代码的大部分工作，就是在不影响其他位的前提下，准确地读写其中某几位。

这类代码出错的后果往往很难直接看出来：多清了一个中断标志，导致偶发丢数据；读改写过程中被中断打断，另一个模块的配置被覆盖；调试器窗口读了一次状态寄存器，标志位就被清掉了。本文从位运算基础讲起，重点放在寄存器访问的工程细节上。

2. 位运算基础与常用宏

操作写法说明
置位reg |= BIT(n)第 n 位置 1，其他位不变
清零reg &= ~BIT(n)第 n 位清 0
翻转reg ^= BIT(n)第 n 位取反
测试(reg & BIT(n)) != 0U判断第 n 位是否为 1
取字段(reg & MASK) >> SHIFT读出多位字段
写字段reg = (reg & ~MASK) | ((v << SHIFT) & MASK)只改字段，其他位保留
 
#include <stdint.h>

#define BIT(n)                  (1UL << (n))
/* 生成 [h:l] 位全为 1 的 32 位掩码，例如 GENMASK(7, 4) == 0xF0 */
#define GENMASK(h, l)           ((0xFFFFFFFFUL >> (31U - (h))) & (0xFFFFFFFFUL << (l)))

#define FIELD_GET(mask, reg)    (((reg) & (mask)) >> __builtin_ctzl(mask))
#define FIELD_PREP(mask, val)   (((uint32_t)(val) << __builtin_ctzl(mask)) & (mask))

FIELD_GET / FIELD_PREP 借鉴了 Linux 内核 bitfield.h 的写法：字段只用一个掩码描述，移位量由掩码自动推导，避免“掩码和移位量不一致”这类低级错误。__builtin_ctzl 是 GCC / Clang 内建函数，在常量掩码上会被编译期求值。

所有位掩码常量都应带 U 或 UL 后缀。1 << 31 在 32 位 int 上是未定义行为，~0x80 得到的是 int 类型的负数，和无符号寄存器混算时容易产生意外的符号扩展。

3. 寄存器访问：volatile 指针与结构体映射

寄存器位于固定地址，读写有硬件副作用，必须通过 volatile 访问，阻止编译器缓存、合并或删除访问。

/* 方式一：按地址访问单个寄存器 */
#define REG32(addr)   (*(volatile uint32_t *)(addr))
#define GPIOA_ODR     REG32(0x40020014UL)

/* 方式二：结构体映射整个外设（CMSIS 的做法） */
typedef struct {
    volatile uint32_t CR;        /* 0x00 控制寄存器 */
    volatile uint32_t SR;        /* 0x04 状态寄存器 */
    volatile uint32_t DR;        /* 0x08 数据寄存器 */
    uint32_t          RESERVED;  /* 0x0C 保留，占位保证后续偏移正确 */
    volatile uint32_t BRR;       /* 0x10 波特率寄存器 */
} demo_uart_t;

#define DEMO_UART1  ((demo_uart_t *)0x40011000UL)

_Static_assert(offsetof(demo_uart_t, BRR) == 0x10, "register map offset mismatch");

结构体映射的好处是一个基地址就能描述整个外设，多个实例（UART1、UART2）共用同一份驱动代码。结构体中的保留字段不能省略，并且推荐用 _Static_assert 检查关键偏移，防止手册版本更新或手误导致整体错位。

CMSIS 中常见的 __IO、__I、__O 分别是 volatile、volatile const、volatile 的别名，用来表达“读写”“只读”“只写”的意图。

4. 读-改-写及其风险

reg |= BIT(3) 实际上是三步：读出寄存器、修改、写回。这在两种情况下会出问题。

4.1 被中断打断

/* 主循环 */
GPIOA->ODR |= BIT(5);        /* 读 ODR = 0x00 */
                             /* --- 此时中断到来，ISR 里执行 GPIOA->ODR |= BIT(6) --- */
                             /* 主循环写回 0x20，ISR 设置的 bit6 被覆盖 */

同一个寄存器被主循环和中断（或两个 RTOS 任务）同时读改写时，必须用临界区保护，或者改用硬件提供的原子置位 / 清零寄存器。

4.2 写 1 清零（W1C）和读清零寄存器

很多状态寄存器的规则是“写 1 清除对应标志，写 0 无影响”。如果对这类寄存器用 |=：

/* 错误：想清 TX_DONE，结果把读到的所有为 1 的标志都写 1，一起清掉了 */
UART->SR |= SR_TX_DONE;

/* 正确：只写需要清除的那一位 */
UART->SR = SR_TX_DONE;

另一类寄存器“读一次就清零”，例如部分芯片的中断状态寄存器、接收数据寄存器。调试时把这类寄存器放进调试器的 Watch 窗口，调试器每次刷新都会读一次，标志就被清掉了，程序里再也看不到中断，现象非常诡异。

写驱动前，先在手册里确认每个寄存器位的访问类型：RW、RO、WO、W1C、RC（读清零）、RS（读置位）。访问类型决定了能否用 |= 和 &=。

5. 原子置位：SET / CLR 寄存器与位带

为了避免读改写竞争，很多芯片为常用寄存器提供了专门的置位 / 清零寄存器。

/* STM32 GPIO：BSRR 低 16 位写 1 置位，高 16 位写 1 复位，单次写入即完成，无需读改写 */
GPIOA->BSRR = BIT(5);           /* PA5 = 1 */
GPIOA->BSRR = BIT(5 + 16);      /* PA5 = 0 */

/* NXP、Microchip 等常见的 SET / CLR / TOGGLE 寄存器组思路相同 */
PORT->OUTSET = BIT(5);
PORT->OUTCLR = BIT(5);

Cortex-M3/M4 还提供位带（bit-band）：SRAM 和外设区各有 1MB 位带区，每一位映射到别名区的一个 32 位字，对别名地址写 0/1 就是原子地修改那一位。

/* 别名地址 = 别名区基址 + 字节偏移 × 32 + 位号 × 4 */
#define BITBAND_PERI(addr, bit) \
    (*(volatile uint32_t *)(0x42000000UL + (((uint32_t)(addr) - 0x40000000UL) * 32U) + ((bit) * 4U)))

BITBAND_PERI(&GPIOA->ODR, 5) = 1U;

位带在 Cortex-M0/M0+、M7、M33 上不可用，新项目一般优先使用芯片自带的 SET / CLR 寄存器或临界区，位带作为了解即可。

6. 多位字段的读写

以一个假设的控制寄存器为例：bit[1:0] 为模式、bit[6:4] 为分频、bit[8] 为使能。

#define CR_MODE_MASK     GENMASK(1, 0)
#define CR_DIV_MASK      GENMASK(6, 4)
#define CR_EN            BIT(8)

enum { MODE_IDLE = 0, MODE_RX = 1, MODE_TX = 2, MODE_FULL = 3 };

void demo_config(demo_uart_t *dev, uint32_t mode, uint32_t div)
{
    uint32_t cr = dev->CR;                       /* 只读一次 */
    cr &= ~(CR_MODE_MASK | CR_DIV_MASK);
    cr |= FIELD_PREP(CR_MODE_MASK, mode) | FIELD_PREP(CR_DIV_MASK, div);
    dev->CR = cr;                                /* 只写一次 */
    dev->CR = cr | CR_EN;                        /* 手册要求先配置后使能时分两次写 */
}

工程上推荐“读到局部变量、在局部变量上改、一次写回”的模式：减少对 volatile 寄存器的访问次数，也让每次写入的值都完整、可预期。很多外设要求在使能位为 0 时才能修改配置字段，这类顺序要求一定要按手册来。

7. 字节序与打包解包

协议和存储格式需要和 CPU 的字节序解耦。不要用指针强转读取多字节字段：既依赖 CPU 字节序，又可能因为地址未对齐触发 HardFault（Cortex-M0 不支持非对齐访问）。

static inline uint16_t get_le16(const uint8_t *p) { return (uint16_t)(p[0] | ((uint16_t)p[1] << 8)); }
static inline uint16_t get_be16(const uint8_t *p) { return (uint16_t)(((uint16_t)p[0] << 8) | p[1]); }

static inline void put_be32(uint8_t *p, uint32_t v)
{
    p[0] = (uint8_t)(v >> 24);
    p[1] = (uint8_t)(v >> 16);
    p[2] = (uint8_t)(v >> 8);
    p[3] = (uint8_t)v;
}

/* 已经是 32 位整数、只需要交换字节时，用内建函数，编译为单条 REV 指令 */
uint32_t net = __builtin_bswap32(host);

8. 常用位技巧

目的写法典型用途
是否为 2 的幂x != 0 && (x & (x - 1)) == 0校验缓冲区容量
向上对齐到 a（a 为 2 的幂）(x + a - 1) & ~(a - 1)内存池块大小、DMA 对齐
取最低位的 1x & (~x + 1)依次处理置位的标志
清除最低位的 1x & (x - 1)遍历位图
统计 1 的个数__builtin_popcount(x)统计在线设备数
最低位 1 的位置__builtin_ctz(x)（x 不能为 0）中断源分发
最高位 1 的位置31 - __builtin_clz(x)（x 不能为 0）优先级位图调度
 
/* 依次处理所有挂起的中断源：每次取出最低位的标志，处理后清除 */
uint32_t pending = DEV->ISR & DEV->IER;
while (pending != 0U) {
    uint32_t bit = (uint32_t)__builtin_ctz(pending);
    handlers[bit]();
    pending &= pending - 1U;
}

Cortex-M3 及以上有 CLZ 指令，__builtin_clz 编译为一条指令；Cortex-M0 上会调用库函数，频繁使用时注意开销。

9. 位图管理资源

位图（bitmap）用一个整数的每一位表示一个资源是否被占用，适合管理固定数量的小资源：DMA 通道、定时器通道、消息槽位、事件标志。

typedef struct {
    uint32_t used;          /* bit = 1 表示已占用，最多 32 个资源 */
} slot_map_t;

int slot_alloc(slot_map_t *m)
{
    uint32_t free_bits = ~m->used;
    if (free_bits == 0U) {
        return -1;                          /* 全部占用 */
    }
    int idx = __builtin_ctz(free_bits);
    m->used |= BIT(idx);
    return idx;
}

void slot_free(slot_map_t *m, int idx)
{
    m->used &= ~BIT(idx);
}

如果分配和释放会在中断和任务中同时调用，used 的读改写需要放进临界区。RTOS 的事件组（event group）本质上也是位图，加上了等待和唤醒机制。

10. 工作场景：一个简洁可靠的 GPIO 驱动

把前面的规则组合起来：结构体映射寄存器、原子置位寄存器输出、字段宏配置模式、读改写处加临界区。下面以一个寄存器布局“示意”的 GPIO 外设为例（实际偏移和位定义以芯片手册为准）。

typedef struct {
    volatile uint32_t MODER;    /* 每个引脚 2 位：00 输入 01 输出 10 复用 11 模拟 */
    volatile uint32_t IDR;      /* 输入电平，只读 */
    volatile uint32_t BSRR;     /* 低 16 位置位，高 16 位复位，只写 */
} gpio_regs_t;

typedef enum { GPIO_IN = 0, GPIO_OUT = 1, GPIO_AF = 2, GPIO_ANALOG = 3 } gpio_mode_t;

void gpio_set_mode(gpio_regs_t *port, uint32_t pin, gpio_mode_t mode)
{
    uint32_t shift = pin * 2U;
    uint32_t primask = irq_save();              /* MODER 需要读改写，其他模块也可能修改同一端口 */
    uint32_t v = port->MODER;
    v &= ~(3UL << shift);
    v |= ((uint32_t)mode & 3U) << shift;
    port->MODER = v;
    irq_restore(primask);
}

static inline void gpio_write(gpio_regs_t *port, uint32_t pin, bool level)
{
    port->BSRR = level ? BIT(pin) : BIT(pin + 16U);    /* 单次写入，天然原子 */
}

static inline bool gpio_read(const gpio_regs_t *port, uint32_t pin)
{
    return (port->IDR & BIT(pin)) != 0U;
}

irq_save() / irq_restore() 的实现见 中断、并发与临界区。这个驱动的取舍很典型：输出用原子寄存器、不加锁；模式配置极少调用，读改写时加一个很短的临界区。

11. 位运算与寄存器检查清单

  • 所有掩码常量是否带 U / UL 后缀，移位位数是否小于类型宽度。
  • 寄存器是否都通过 volatile 访问，结构体映射的保留字段和偏移是否用 _Static_assert 校验。
  • 每个要操作的寄存器位，是否确认了访问类型（RW / RO / W1C / RC）。
  • W1C 寄存器是否误用了 |=；读清零寄存器是否被调试器 Watch 窗口意外读取。
  • 同一个寄存器是否被多个上下文读改写，是否改用 SET / CLR 寄存器或加临界区。
  • 多位字段是否先清后写，是否遵守“先配置、后使能”的顺序要求。
  • 多字节字段的读写是否通过显式字节序函数，而不是指针强转。
  • 使用 __builtin_ctz / __builtin_clz 时，是否排除了输入为 0 的情况。
